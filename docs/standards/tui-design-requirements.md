# TUI 设计要求

本文定义 lx-tui 的界面布局、样式 Token、交互与降级规则。第一版布局参照 herdr 做最小实现。

## 总体布局

```text
┌──────────┬─────────────────────────────────┐
│          │ 标签栏                     [EXIT]│
│  侧栏     ├───────────────────────┬─────────┤
│          │ 主区域（窗格平铺）      │ prompt  │
│          │                       │  右栏    │
└──────────┴───────────────────────┴─────────┘
```

- 固定顺序：侧栏（左，占据全高）、标签栏（横跨主区与 prompt 栏的顶部）、主区窗格平铺；prompt 栏默认为右栏（在标签栏下方，顶边与底边同主区窗格对齐），可通过主区与 prompt 分隔线正中的交换按钮切到主区左侧。
- 第一版允许只有一个窗格，但区域划分必须按多窗格设计；窗格几何由根级 `src/layout.rs`（BSP）计算，区域划分集中在 `ui/layout.rs`。

## 区域职责

- 侧栏：工作区/会话一级导航；支持折叠；激活项使用强调色填充（青底黑字）；鼠标悬停的非激活项整行铺深色高亮（`style::selection`：Indexed 240 底、Indexed 255 字，同右键菜单选中项）；行内特殊文字（分组折叠箭头 accent、agents 状态圆点状态色、`*` 与去重序号 accent）保留自身前景与修饰符，悬停只叠加高亮底色、不覆盖其颜色；其余项不使用整行反白，也不使用背景色。竖直中线处为 agents 分区表头：无两端竖线的横线与左对齐标题 `Agents`（与顶部 Workspaces 标题同列，标题用与其他边框标题一致的 `style::border_title` 淡蓝色），右端折叠按钮与面板折叠按钮同列；表头之上为 Workspaces 列表，之下为 agents 分区：列表展示当前激活工作区各窗格中已识别 Agent 的条目（行首 `❯` 标记聚焦窗格，随后状态圆点（Working 绿实心 `●`、Blocked 黄实心、Idle/Unknown 弱化空心 `○`）+ Agent 名称 + 右对齐 muted `[tab N]`；空分区显示 muted `no agents running`，溢出时右缘滚动条样式同 workspaces；左键点击条目切换该 Tab 并聚焦对应窗格）；点击折叠后分区内容收为 0 行、表头贴底边框上一行。侧栏顶边框右端（原折叠按钮位置，距右边框 1 列）为新建按钮 `[+]`：点击立即创建并激活单窗格 `shell` 工作区，目录取当前工作区焦点终端窗格的实时 cwd（回退该工作区主终端 cwd、进程 cwd），名字取目录末段（HOME 显示 `~`、根路径显示完整路径），与现有工作区重名时追加最小未用序号；侧栏底边框左端（距左边框 1 列、与右端折叠按钮同列）为设置按钮 `[SET]`（纯 ASCII 文案、逐格强调色绘制，与折叠按钮同款样式；设置服务不可用、侧栏折叠或过窄时隐藏，hover 显示 `open settings` tooltip）：点击由事件层在系统默认浏览器打开本地设置页（回环服务、随 TUI 退出关闭），`ui/` 不做 IO；工作区路径与 git 归属在创建时确定后保持不可变，不随窗格内 `cd` 漂移（窗格各自跟踪 cwd，仅用于标题与新建工作区取目录）。启动时创建的工作区在名字后显示不可移除的 `*` 标记（表示最初进入的路径，用强调色 accent 标识，悬停不改变其颜色），名字超宽先截断以保证标记可见。工作区按 cwd 识别 git checkout 元数据（`git worktree list --porcelain`，后台查询）：同一仓库有 ≥1 个 linked worktree 且含非 linked 主项时成组，树根固定为创建最早的非 linked 主项（按根窗格标识序，拖拽换位不改变）；顶层项（组父项、重复主 checkout 与非 git / 未分组工作区）统一缩进 2 列、名字同列，根之后（索引更大）的 linked worktree 项在缩进列用 `├─ ` / `└─ ` 树形连接符（末位按可见子项判定）并显示分支短名（去掉 `worktree/` 前缀）作标签；同一组内 linked 标签重复时在名字后追加最小未用序号（2、3…，含被折叠隐藏的子项保持稳定，与 `*` 同用强调色 accent），`*` 标记排在其后，手动命名的工作区仍显示自定义名。组父项行在左缘显示折叠箭头（`▾ ` 展开 / `▸ ` 折叠，accent 色，占 2 列），父项名字与子项连接符同列，仅点击箭头格切换折叠，父项行其余区域仍为切换工作区与拖动；折叠后仅保留父项与当前激活子项，折叠状态按仓库根路径仅存内存（重启恢复展开）；列表不做父项前置重排，渲染、命中与滚动按可见行映射（被隐藏的子项不可点击/拖动）。打开 linked worktree 时（Open 对话框、启动 cwd、`[+]` 新建首次识别到元数据）若其仓库主 checkout 尚未打开，自动在该仓库首个成员之前插入主工作区（shell 在主 checkout 启动），保证树形结构始终成立。列表项左键单击切换当前工作区（右侧 prompt 随之切到该工作区草稿；钉住时保持不变），按住上下拖动可实时重排：被拖项所在组（根 + linked 子项，折叠隐藏的子项同样跟随）整体移动，指针移动后组内可见行整行反显（按下未移动不反显，直接显示整行选中态，保证单击切换一次成型），重复主 checkout 独立单项移动，落点落在别的组上吸附到该组上/下边界（不插进组中间）；松手完成，激活项与 `*` 标记跟随条目移动；仅支持可视范围内排序，不做边缘自动滚动，右键弹出菜单（`New terminal` / `Open worktree` / `Open prompt` / `Rename` / `Close`；`New terminal` 在目标工作区追加直接进入终端视图的标签并以该工作区固定路径启动；`Open prompt` 展开并聚焦 Prompt 且切换激活该工作区；`Open worktree` 仅当该工作区已有 git 元数据时显示，`Close` 仅剩一个工作区时不显示）；列表溢出时右缘一列显示滚动条（滚轮每格 1 项、轨道点击跳转、拖拽 thumb），创建/切换/关闭后自动保证当前项可见。侧栏展开宽度可拖拽调整：最小 18 列、最大 40 列，且不把主区挤到小于最小窗格宽度；折叠态不可拖拽。
- 标签栏：切换当前工作区内的标签；标签标题未重命名时按位置动态显示 `tab N`（关闭后自动重新编号），重命名后显示自定义名；激活标签使用强调色填充（青底黑字，不含尾部竖线分隔符），鼠标悬停的非激活标签使用终端原生反显（同样不含分隔符），其余标签保持 muted；左键单击标签切换（清除选区、收回 prompt 焦点）；每个标签后紧跟竖线分隔符。最后一个标签之后为新建按钮 `[+]`（强调色）：左键单击立即新建并激活一个标签（不弹命名框），PTY 按状态对齐启动；标签总宽超出可视区时自动切换为滚动布局：左端 `[<]`、`[+] [>]` 依次贴退出按钮左侧，标签按完整标签宽度逐格滚动，不可滚方向按钮置灰，未溢出时不显示滚动按钮；新建/切换/关闭标签、切换工作区或窗口缩放后自动保证激活标签完整可见。右键标签弹出菜单 `New tab / Rename / Close`（仅剩一个标签时不显示 `Close`），`New tab` 立即新建并激活，`Rename` 弹出重命名浮层预填当前标题，`Close` 弹出二次确认；标签重命名/关闭操作与工作区同名规则一致。最右端为退出按钮 `[EXIT]`，贴屏幕右缘，右缘与右栏折叠态按钮对齐，左键单击退出应用。

## 浮层与模态

- 浮层（toast、右键菜单、命令面板、模态容器）统一铺自包含面板底色：`ui/style.rs` 的 `overlay_panel`（Indexed 236 底、Indexed 252 字），整块含边框不透明，透明终端下不透视底层；浮层内选中/悬停项使用高亮中灰底白字（`overlay_selection`：Indexed 240 底、Indexed 255 字），彻底杜绝反显修饰符在半块字符与透明终端上的黑边反噬。
- 浮层清底统一走 `ui/widgets/clear.rs`（`clear::render` / `render_buffer`），不得直接用 `ratatui::widgets::Clear`：底层宽字符（中文/emoji）会把右半格标记为 diff 跳过，若浮层边缘正好切在该宽字符中间，ratatui 的 diff 会因「另一半未变」整格跳过相邻单元格，导致左边框缺格或右边框外残留半个字。清底助手会把被浮层两侧边缘切成半格的底层宽字符擦成空白（保留其底色与修饰符），使其在 diff 中重新下发，保证浮层边框完整。
- 全局 toast 是非模态反馈：同一时刻只显示一条，新消息替换旧消息；锚点容器内顶边框下方水平居中，容器过窄、缺失或未指定锚点时降级到屏幕顶部居中；绝对定位、不改变底层布局尺寸，默认 2 秒自动消失，hover 期间暂停消失。边框用语义色（三档：`Info` 强调青、**`Warning` 警告黄**（取 `style::agent_warn`，与聊天历史「中断」同一档，不新增黄色）、`Error` 失败红；三档两两不同，由 `ui::toast::tests::warning_toast_border_is_yellow` 守住），标题以 muted 显示在顶边框（复制反馈为 `Clipboard`），正文居中占一行；顶边框右上角常显 `[✕]` 关闭按钮：点击 `[✕]` 或点击 toast 之外关闭（点击 toast 内部内容不关闭；外部点击关闭 toast 后继续处理本次点击）。
- 引入对话框、命令面板等模态浮层时：同一时刻只处于一个模式，浮层出现时保持底层画面可见，`Esc` 可关闭，且不得改变底层布局尺寸。居中模态（重命名/新建工作区/确认/信任/worktree/保存草稿）顶边框右上角常显 `[✕]` 关闭按钮：点击浮层内部内容（非按钮/条目/输入区域）不关闭，仅点击 `[✕]` 或浮层之外关闭；右键菜单内部空白同样保持打开、点击菜单外关闭（菜单不设 `[✕]`）。模态内的单行输入框（重命名/新建工作区/新建节点/worktree 搜索/保存草稿名称）左侧统一 `>` 前缀（置于输入区左侧、不占输入内容），与 prompt 列表搜索框一致。
- 右键菜单：菜单项固定按「新建/打开 → 切换/导航 → 重命名 → 关闭」分组排序，`Close` 恒为最后一项，条件项在所属组内原位显隐；锚点定位并夹取屏幕内；顶边框显示 muted 标题（工作区名 / 标签名 / 窗格标题，取不到时回退 `workspace` / `tab` / `pane`）；`Esc` 关闭、`↑/↓` 循环移动高亮、`Enter` 执行当前项、鼠标悬停跟随高亮、点击菜单外关闭且不穿透；打开期间接管键盘，其余按键一律不写入 PTY。
- 重命名浮层：居中模态；预填当前名字、光标在末尾；底部按钮 `[save enter] [clear ^c] [cancel esc]`（名称在前、快捷键在后），按钮可点击；`Enter` 保存（trim 后为空则拒绝且浮层保持打开）、`Esc` 取消、`Ctrl+C` 清空输入；点击 `[✕]` 或弹窗外取消（点击弹窗内非按钮区域保持打开）；硬件光标与输入位置同步，视口与光标按显示宽度滚动（宽字符按两列计，与 prompt 编辑器一致）。
- 关闭确认浮层：居中模态；问题行（超出弹窗宽度时按显示宽度自动换行——优先空白断行、超宽单词按字符硬断，弹窗高度随行数增长，极端超长时末行以 `…` 截断）+ 底部按钮 `[confirm enter] [cancel esc]`；`Enter` 确认、`Esc` 或点击 `[✕]`/弹窗外取消（点击弹窗内非按钮区域保持打开）；确认后终止该工作区全部 PTY 并移除，关闭当前工作区时焦点落到同索引、越界回退末项；至少保留一个工作区。
- 切换工作区路径确认浮层：居中模态；问题行完整展示目标路径（弹窗宽度随路径展开、超出屏幕时夹取并按显示宽度自动换行），底部按钮 `[confirm enter] [cancel esc]`；确认后向目标窗格写入转义并双引号包裹的 `cd "路径"` 命令（保留用户 Shell 环境变量与历史），`Esc` 或点击 `[✕]`/弹窗外取消（点击弹窗内非按钮区域保持打开）。
- 右键菜单与模态尺寸按终端显示列（`UnicodeWidthStr::width`）计算，正常窗口下菜单项与标题完整显示、不做省略，仅在物理宽度不足时夹取到屏幕宽度。
- worktree 对话框：居中模态；顶部搜索行（占位 `filter worktrees`，输入即过滤名字/目录名/路径/状态，不区分大小写）、分隔线、两行条目（上行 `› 分支名或目录名` + 右对齐状态 `open` / `detached` / `root`，下行缩进路径）与底部按钮 `[open enter] [cancel esc]`；`↑/↓` 在过滤结果内移动（不循环），`Enter` / `[open]` 打开选中项（已作为工作区打开时直接切换、不重复创建、不做信任检查；否则先对仓库主 checkout 做信任检查——已信任直接放行且不单独入库，未信任弹信任浮层、确认后以该 checkout 为 cwd 新建工作区并带入 git 元数据、拒绝则取消并 Toast），`Esc` / `[cancel]` / `[✕]` / 点击弹窗外关闭（点击弹窗内非控件区域保持打开）；条目点击高亮，加载中显示 `loading…`、失败显示 `failed to list worktrees`、空列表显示 `no worktrees found`；列表查询在后台执行，不阻塞事件循环。
- 需要确认的破坏性操作（关闭窗格等）必须二次确认。
- 工作区信任：分两层实现。
  - 启动信任页（进入应用前，行内显示，参考 Claude Code）：`lx` 在未信任目录启动时**不进入应用、不进入备用屏幕**，先清屏并在当前终端屏幕（原始模式 + 鼠标上报）**左上对齐**绘制信任页（无居中浮层、无对话框底）：**全宽 `─` 分隔线在最上方**，其下左对齐 LX 像素 logo（放不下时省略），内容一律左侧 1 列缩进——`Accessing workspace:`（加粗）、中间省略的目标路径（accent 高亮）、安全提示段落（`Quick safety check:` 前缀加粗）、能力说明（加入工作区并可在其中读写执行文件；提示词管理：创建、文件夹组织、编辑与删除，均本地持久化）、两个可选项 `No, exit`（前、默认选中）/ `Yes, I trust this folder`（选中项整行全宽高亮 + 行首 `▸` 标记）与页脚 `[↑/↓] select  [enter] confirm  [esc] cancel`；宽度不足时长段落自动换行，高度不足时按「说明 → 空行 → 安全提示 → 页脚 → logo」的顺序逐级省略（最小 40x10 仍完整展示标题、路径与选项）。`↑/↓`（鼠标悬停跟随）切换选中，`Enter` 或鼠标左键点击选项确认，`Esc` 取消，`y`/`n` 为快捷选择（选择条全宽，对齐 Claude Code）；选择 `Yes` 清屏归位、录入本地库（`is_trusted = 1`）后进入应用备用屏，选择 `No` 清屏后输出 `workspace not trusted; exiting` 并以 0 退出，不进入应用。本地库不可用时视为放行（不因持久化故障阻断应用）。
  - 应用内信任浮层：居中模态；标题 `Trust workspace`，问题行 `Do you trust the files in this folder?`、高亮展示目标路径（超宽按显示列中间省略）与底部按钮 `[trust & open enter]` / `[don't trust esc]`；`Enter` 或点击 `[trust & open]` 信任并继续（路径以 `is_trusted = 1` 录入本地库），`Esc` 或点击 `[✕]`/浮层之外拒绝：新建工作区与打开 worktree 时取消创建、终端同步时取消同步（均保留原状态并 Toast 告警）；点击浮层内非按钮区域不动作。显式路径新建工作区、worktree 对话框打开条目与终端右键 `Sync ws to terminal path` 触发前都会先做信任检查，已信任路径直接放行。**信任目标归位**：git 工作区的检查与登记目标为其**仓库主 checkout**——worktree 目录随主 checkout 的信任状态放行、不单独入库；显式路径先查路径自身（兼容历史 worktree 信任行），未命中时由事件层后台解析仓库根（不阻塞 UI）；启动信任页同样归位到仓库主 checkout（启动目录在已信任仓库的 worktree 内时直接进入）。

## 配色与样式

- 样式只从 `ui/style.rs` 的语义函数取用（`text` / `muted` / `accent` / `border` / `selected_item` / `selection` / `right_tab_active` / `right_tab_hover` / `overlay_panel` / `overlay_selection`），禁止在组件中直接写死颜色与修饰符。
- 面板边框标题统一用 `style::border_title`（淡蓝色：Cyan + dim、不加粗，与分支状态同色系；焦点/浮层的强调色边框不改变标题观感），覆盖侧栏、窗格、prompt、toast、右键菜单与模态弹窗；按钮（折叠按钮、视图切换按钮、prompt 工具栏按钮、`[EXIT]`、`[+]` 等）保持强调色。
- 配色沿用 codex：跟随终端原生 ANSI 色——正文使用终端默认前景，次要信息用 `dim`，强调/焦点用 `Cyan` 加粗；状态色沿用 codex 语义（成功 `Green`、失败 `Red`、注意 `Yellow` 仅在已知暗色终端使用）。
- **markdown 高亮分两套互不复用的色板**（用户要求两者独立，不得混用）：① **阅读渲染**（`ui::markdown_render`，lx 历史正文）**照抄 GitHub Dark 官方色板**（固定 RGB，不做主题映射、不做背景；仅经 `ui/style.rs` 的 `github_dark` 模块与 `md_read_*` 语义函数取用）：语法 token 取 prettylights 变量——关键字/类型声明 `#ff7b72`、字符串 `#a5d6ff`、常量/数字/行内代码 `#79c0ff`、实体/类型名 `#d2a8ff`、注释 `#8b949e`；文档结构取 github-markdown-css 的 dark 变量——链接与裸 URL `#4493f8`，引用/语法标记/表格与水平线/代码语言标记/图片说明/任务项 `#7d8590`；**结构性强调不上色**（标题、粗体、粗斜体、斜体、删除线、代码正文一律终端默认前景 + 修饰符，h1/h2 用下划线模拟 `border-bottom`，引用不加斜体）；**三处例外**（都不动正文）：① **列表符号与有序序号用链接蓝 `#4493f8`**（`md_read_bullet` / `md_read_ordered`；GitHub 自身列表符号与正文同色，终端里同色会让列表结构完全看不出来），② **任务列表复选框按状态分色**（`md_read_task_done` 绿 / `md_read_task_open` 黄，**只染 `[x]`/`[ ]` 本身**；已完成项不再整行加删除线或压暗——任务状态只由复选框表达，文字仍须可正常阅读），③ **代码块格式**：**只画代码正文**——围栏、左侧竖条、`language: xxx` 头部、复制按钮与上下分隔横线全部移除（用户要求「直接显示代码」）。语法高亮照旧按语言做轻量分词（关键字/字符串/数字/类型/注释），代码块与正文之间只靠配色区分；移除容器装饰后窄宽度不再被横线与按钮挤掉列，也不再需要为复制按钮维护一套命中几何。行内代码 `xxx` 保持纯前景色 `#79c0ff`、不铺背景。
② **编辑器高亮**（`ui::prompt::token_style`，prompt 编辑器与 lx 多行输入框共用；`markdown_*` 语义函数）是**独立的第二套色板**，保留 ANSI 语义槽位以便打字时一眼分色：标记 `dim`、标题/粗体/斜体 `Yellow`、删除线与行内代码 `LightRed`（`markdown_inline_code` 纯前景、不铺背景）、**无序/有序列表符号 `Yellow` 加粗**（`markdown_bullet` / `markdown_ordered`）、**任务复选框按状态分色**（`markdown_task_open` 黄 / `markdown_task_done` 绿）、**标题 `#` 专用高亮**（`markdown_heading_marker` = Yellow + dim，与正文通用 `Marker` 的 dim 灰区分）——列表标记与任务复选框、标题标记均由通用 `Marker` 拆为独立语义 token（`TokenKind::ListBullet` / `ListOrdered` / `TaskOpen` / `TaskDone` / `HeadingMarker`），只染符号、正文原色、引用 `LightMagenta` 斜体、链接文字 `LightBlue` 下划线、URL `Cyan`、`@` 提及 `Yellow` 下划线、`@[refer-file]` 亮绿下划线、`@[refer-folder]` `Indexed 208` 下划线、`@[refer-image]` 亮品红下划线、`@ref/` 短引用 `Indexed 141` 加粗。改动任一侧不得影响另一侧（`ui::style::tests` 的 `markdown_palette_is_github_dark_truecolor`、`editor_palette_stays_ansi_and_independent_from_reading` 与 `markdown_palette_is_disjoint_from_chat_steps` 守住）。此前两版（全员 ANSI 多色相、全员一刀切去色相）都已废弃。
- 默认不铺自绘背景，保持终端透明；不使用 RGB、渐变、阴影或动画。例外一：侧栏/标签栏选中行的整行背景（仅 ANSI-16 的 `Cyan`，经 `ui/style.rs` 的 `selected_item` 取用）；悬停行使用深色高亮背景（`selection`：Indexed 240 底、Indexed 255 字，与右键菜单 overlay_selection 对齐），不使用反显修饰符。右侧容器顶边框的标签页同样铺实心块，但**必须与顶部标签栏区分色相亮度**：激活经 `ui/style.rs` 的 `right_tab_active`（Indexed 24 深青蓝底、Indexed 255 字、加粗），悬停经 `right_tab_hover`（Indexed 237 暗灰底、Indexed 252 字、不加粗）——两处同款青底会让"当前工作区标签"与"当前右侧面板"看起来是同一种选中态。例外二：lx 页品牌 logo 像素画与入口标签文字色使用 256 色 Indexed 调色板（logo 经 `ui/style.rs` 的 `logo_pixel` 取色、标签渐变经 `lx_entry_label_style` 取色），**lx 聊天历史的步骤标记按类别分三档**（正文 = 终端默认前景 `chat_step_*_body`；思考 = 品红 `Indexed 218` `chat_step_*_thinking`；工具 = 翡翠绿 `Indexed 42` `chat_step_mark_running`/`chat_step_mark_done`/`chat_tool_verb`；可变参数 `chat_tool_param` = **终端默认前景**（不设 fg、不加修饰符；用户要求参数改用默认字体色，工具行的颜色信息只由方块 / 动词承担）；只读元信息 `chat_tool_range` = `muted()` dim 无色相；有色档与参数不压暗）。**它与例外五的 GitHub Dark 高亮在色域上不相交**：GitHub 的 6 个代码 token 已把蓝（207°/208°/212°/214°）、紫（269°）、珊瑚红（4°）占满，256 色里唯一还剩 ≥30 CIEDE2000 色差余量的空闲色相是绿/青绿（120°–170°），结构色因此定在 `Indexed 42`——与正文色差 30.1、与全部 GitHub 代码色最近 32.8，两项同时 ≥30（上一版用的 lx 标签浅蓝 `153` 与正文只差 11.5、与 GitHub 字符串蓝只差 2.1，是用户带截图反馈「与小方块与正文内容颜色特别相近」的根因）。两侧任一向另一侧色域漂移都由 `ui::style::tests` 的 `markdown_palette_is_disjoint_from_chat_steps` 与 `chat_step_palette_uses_amber_for_running_and_green_when_done` 拦住。其余区域维持原规则。例外三：四类浮层（toast、右键菜单、命令面板、模态容器）的整块面板底色（仅经 `ui/style.rs` 的 `overlay_panel` 取用：Indexed 236 底、252 字）。例外四：模板块整块状态底色（仅经 `ui/style.rs` 的 `template_block_bg` 取用：低饱和暗 RGB——todo 35,40,56 / in_progress 51,41,28 / done 29,46,36）。例外五：markdown 阅读高亮使用 GitHub Dark 官方色板的固定 RGB（仅经 `ui/style.rs` 的 `github_dark` 模块取用：`#ff7b72`/`#a5d6ff`/`#79c0ff`/`#d2a8ff`/`#8b949e`/`#4493f8`/`#7d8590`），理由与边界见上文 markdown 高亮条目。
- 光标统一使用终端原生硬件光标（不自绘反显块），且 TUI 运行期间关闭闪烁、保持终端配置的光标形状：进入时下发 DEC 私有模式 12（`\x1b[?12l`），退出恢复（`\x1b[?12h`），不支持的终端静默忽略。原因是动画/高频重绘会重置部分终端（Ghostty 等）的光标闪烁相位，硬件光标的闪烁无法在重绘下稳定维持，只能整体关闭。同一时刻只有一个硬件光标（优先级：浮层输入 > prompt 编辑器 > 焦点窗格；非模态下光标位置被后绘制的 tooltip/toast 盒覆盖时隐藏，避免覆盖浮层），单行输入（如重命名）与多行编辑器共用同一套显示宽度光标/视口规则。高频重绘（如终端输出）不得每帧重复下发光标指令：`tui/` 的光标去重后端只在可见性变化时下发 Hide/Show，只在内容 diff 可能移动物理光标或目标位置变化时下发 MoveTo。
- 帧提交使用终端同步更新（DEC 2026）：每帧以 `BeginSynchronizedUpdate` / `EndSynchronizedUpdate` 包裹提交，支持该模式的终端整帧原子呈现（选中/hover 背景切换不会逐格涂抹）；不支持的终端静默忽略、保持原绘制路径。
- 明暗终端均须可读：不得使用暗灰等只在单一背景色下可读的前景，`dim` 的对比度交给终端保证。
- 无主题切换；如需差异化外观，优先调整终端自身配色。浮层使用 `Clear` 重置底层内容后绘制。

## 窗格内容

- 窗格内运行真实 PTY 进程（默认 `$SHELL`），终端仿真用 `alacritty_terminal`（纯内存），渲染只读网格。shell 按窗格所属工作区的 cwd 启动：打开 worktree 的工作区即为该 checkout，分割窗格与新标签继承工作区跟踪到的当前目录。
- 焦点窗格把硬件光标同步到仿真光标处（IME 预输入与候选随硬件光标显示），显示与闪烁由终端原生光标承担；隐藏光标由程序模式决定，失焦、程序隐藏或光标滚出视口时硬件光标一并隐藏。
- 宽字符占位单元格必须标记为 diff 跳过，禁止渲染出半个字符。
- 窗格标题优先使用程序通过 OSC 设置的标题（claude code、codex 等程序依赖该通道）；未设置 OSC 标题时显示该窗格 shell 进程 cwd 的标签（复用工作区命名规则：HOME 显示 `~`、根路径显示完整路径、其余取末段），读不到 cwd 时回退为 `pane N`；进程退出后标题追加 `(exited)`，保留最后一屏。
- 终端模式（DECCKM、括号粘贴等）决定按键与粘贴编码，编码集中在 `input/encode.rs`。
- `placeholder` 窗格为空占位：不启动 PTY、无内容，标题沿用 `pane N`。
- prompt 右栏是独立于终端仿真的 markdown 编辑器（不启动 PTY）：草稿按工作区隔离，每工作区各持一份编辑器状态（文本/撤销/选区/@ 面板/显式上下文根），切换工作区即切换到该工作区草稿，在途 @ 扫描结果按编辑器标识路由回所属草稿；点击聚焦并定位光标，支持字符/换行、退格/删除、方向键/Home/End、readline 编辑键（`Ctrl+U` 删除到逻辑行首、已在行首时删除前一个换行并合并上一行，`Ctrl+K` 删除到逻辑行尾、`Ctrl+W`/`Ctrl+Backspace` 向前删词、`Ctrl+Delete`/`Alt+D` 向后删词、`Ctrl+A/E` 逻辑行首/尾、`Ctrl+D` 正向删除、`Ctrl+←/→` 与 `Alt+B/F` 按词移动）、撤销/重做（`Ctrl+Z`/`Ctrl+Y`，并接受 `Ctrl+Shift+Z`、`Ctrl+-`、`Ctrl+.` 与 `Super` 组合；快照历史上限 200 `&&& <name>Template --start` + 次行行首 `{title: }` 标题占位行（`{title:` 前缀与收尾 `}` 为结构标记、不可删除或局部改写，仅值内可编辑；除非整行随块删除）+ 空行（渲染为块边框分割线）+ 正文 + 空行（块底部留白）+ `&&& <name>Template --end` 模板块（标题占位行与起止行同款 `{key: value}` `-[wt]`（条目不另标来源，目录与文件同一列表；绑定主 checkout 时不弹选择器、标题无后缀；分支缺失或歧义时该块 @ 候选不可用、不回退显式根）；选择器内 `↑`/`↓` 循环切换 main/wt，高亮在同一会话内保持、不因按键前的上下文根同步复位，回车或左键确认高亮项；选中 `/gitWorkTree` 先把命令行整行回显为规范命令文本 `/gitWorkTree 复制语义提取正文（剔除标题占位行、`+++` 补充子块及其内容、保留 `%%%` 记录子块内容但剔除其标记行、剔除 `//` 注释行与未填写空项）并 toast 反馈；`Ctrl/Cmd+Shift+C` 复制光标所在 `&&&` 模板块或 `+++` 补充子块的同一份正文（光标在补充子块内时优先取该子块，不在块内不动作）。标题占位符用 Cyan 下划线（与状态色边框、@ 提及黄区分）；标题行下与 `{wt:}` 上方的空行不写入任何文本，渲染为块边框分割线（`├─…─┤`，随块状态取边框色）；块底部（结束行上方）的结构空行同样不写入任何文本、按普通空行渲染（不画分割线；正文中的其它空行亦按普通空行渲染）。
- 左右栏均可折叠：展开态在底边右端显示折叠按钮，左栏为 `[◀]`、右栏为 `[▶]`；折叠后压缩为 4 列窄条（3 个内容列 + 1 列贴主区一侧的分隔线，左栏在右缘、右栏在左缘），条内不显示文字内容，仅在底行内容区水平居中显示反向箭头标签（左栏 `[▶]`、右栏 `[◀]`，恰好占满 3 个内容列）；箭头指向点击后的移动方向；按钮使用强调色以区别于普通文字，仅通过鼠标点击切换；左右栏折叠期间各自分割线不可拖拽，展开恢复折叠前宽度。任一时刻只有右列面板可折叠：prompt 默认占右列；交换后右列为主区，折叠按钮与能力随之转移（prompt 在左不可折叠）。主区折叠为贴屏幕最右缘的 4 列窄条（分隔线朝主区一侧）、不重排终端 PTY（仅隐藏渲染），折叠期间 prompt 占满其余宽度，展开恢复折叠前宽度。主区与 prompt 的分隔线垂直正中另有 2 列宽交换按钮（左格 `<`、右格 `>`，强调色，悬停显示 `swap prompt side` tooltip）：左键点击后 prompt 与主区窗格左右互换（侧栏、标签栏与 `[EXIT]` 不动），两栏同时恢复展开，右列重置为默认 2/5 侧栏宽、左列占其余宽度（点两次完整还原默认布局）；按钮命中优先于分隔线拖拽，悬停这 2 格不高亮分割线、不显示拖拽指针；面板内容高度不足 3 行时隐藏，右列折叠期间按钮仍可点击。

## 交互

- 应用级快捷键只保留 `Ctrl+Q` 退出（prompt 聚焦与浮层打开时同样生效）；浮层打开时按键按浮层种类过滤（菜单 `Esc/↑/↓/Enter`、重命名 `Esc/Enter` 与单行编辑键、确认与信任 `Esc/Enter`），其余吞掉；prompt 聚焦时其余按键映射为编辑器命令（readline 与列表编辑子集，树视图下改为上下移动选中、回车激活、左右折叠展开），未映射按键吞掉；其余情况按键（含 `Ctrl+C`、`Tab`）一律原样编码进焦点窗格，不存在前缀状态机与应用键位。
- 鼠标承担全部交互：点击 prompt 内容区聚焦编辑器并定位光标，滚轮悬停在 prompt 上时按 3 个视觉行滚动其视口（拖拽选区期间不滚动）；点击终端窗格聚焦该窗格并收回 prompt 焦点；左右栏底边与 agents 表头的折叠按钮分别切换对应面板/分区；标签栏右端的退出按钮单击退出应用；主区与 prompt 之间、侧栏与主区之间的分割线均支持拖拽调整对应栏宽，分隔线正中的 `<>` 交换按钮单击互换 prompt 与主区位置；左键单击侧栏工作区项切换工作区（清除选区、收回 prompt 焦点），右键工作区项打开菜单；滚轮悬停在 workspaces 区滚动工作区列表（每格 1 项），滚动条轨道可点击跳转、thumb 可拖拽；浮层打开期间鼠标点击只作用于浮层，不穿透底层；浮层内列表（引用文件夹目录弹窗、引用文件夹内容搜索弹窗、prompt 的 `@`/`/`/块命令面板等）滚轮一律只滚动视口、不移动高亮（越界钳制不循环，高亮可被滚出视口，键盘移动后窗口重新跟随高亮），溢出时右缘一列显示滚动条（**只画 thumb `▐`、不画轨道竖线**，轨道点击跳转、拖拽 thumb 实时滚动），与 prompt 列表一致；引用文件夹目录弹窗的鼠标悬停只给该行铺 `overlay_selection` 底色、不移动 `❯` 选中标记（`❯` 只由点击与键盘移动，选中行只显示 `❯` 标记、不铺底色），对齐 prompt 树列表的「选中给标记、悬停给底色」语义。
- Unix 用显式 VT 序列上报按键/释放/拖动/移动（SGR 1000/1002/1003/1006），Windows 走 crossterm 的 WinAPI 捕获；移动上报仅用于分割线悬停反馈。
- 分割线只命中相邻两列边框（主区最右窗格右边框、右栏左边框），不侵入内容区；顺序执行折叠按钮命中优先，prompt 滚动条槽命中优先于编辑器点击；拖拽与文本选择互斥，按下清选区、松开只结束拖拽且不写剪贴板。
- 悬停或拖拽分割线时，两列边框改为强调色；同时通过 OSC 22 把鼠标指针设为 `ew-resize`，离开显式发 `default` 恢复（空 payload 部分终端不认，不支持的终端静默忽略、高亮兜底）。
- 右栏宽度拖拽与窗口缩放都保证两侧不小于最小宽度（`min_pane_width`，默认 10 列，含边框）；可用宽度不足两个最小值时均分。

## 选择与复制

- 终端窗格与 prompt 编辑器支持文本选择；空占位窗格没有内容，不参与选择。
- 交互：左键按下即定位光标并锚定选择，拖动实时反显高亮且光标跟随释放点；终端窗格松开时非空选区写入系统剪贴板并清除选区（空选区与全空白选区视为无可复制内容，仅清除选区、不提示），写入结果通过全局 toast 在选区所在窗格反馈（成功 `Copied to clipboard`、失败 `Copy failed`）；prompt 松开后保留选区高亮，按 `Ctrl/Cmd+C` 复制：有选区复制选区原文，无选区复制全文（同样 toast 反馈；内容为空不提示），`Ctrl/Cmd+Shift+C` 复制光标所在模板块正文（对齐 lx-agent 的 `Mod-Shift-C`；legacy 终端不区分 Shift 时退化为普通复制），滚轮滚动其视口、折叠或尺寸变化时清除选区。
- 终端文本提取交给终端仿真器（`alacritty_terminal` 的 Selection），宽字符、换行与行尾空格由其处理；选择范围仅限当前视口。
- prompt 选区按渲染后的视口行列坐标映射回文本字节偏移，软换行连续行不插入换行、宽字符整字命中；复制时提取原文写入剪贴板；有选区时输入类按键用新内容替换选区、`Backspace`/`Delete` 删除选区（一次撤销即可恢复），其余编辑命令先清除选区。
- 剪贴板写入（参考 opencode）：OSC 52 立即写（tmux/screen 自动加 passthrough 包装）；原生工具（macOS `pbcopy`、Windows PowerShell `Set-Clipboard`、Linux `wl-copy`/`xclip`/`xsel`）在后台线程限时执行，绝不阻塞事件循环；OS 代码只出现在 `src/platform/`。
- 文本/列表选区高亮使用终端原生反显（REVERSED）；条目选中背景只允许侧栏与标签栏且收口在 `style.rs` 的 `selected_item`，右侧容器顶边框标签页另收口在 `style.rs` 的 `right_tab_active` / `right_tab_hover`；鼠标悬停高亮收口在 `selection`（Indexed 240 底、Indexed 255 字，不用反显修饰符），行内特殊文字（agents 状态圆点状态色、accent 标记与状态计数）悬停时保留自身前景与修饰符，只叠加悬停底色。
- macOS 终端默认把 `Cmd+C` 绑到终端自身的复制动作（Ghostty/iTerm2/Terminal.app 均如此）：应用捕获鼠标时终端没有原生选区，该键被吞掉、到不了应用。Ghostty 用 `keybind = performable:super+c=copy_to_clipboard` 即可在无原生选区时把 `Cmd+C` 以 kitty 协议（`CSI 99;9u`）下发给应用；不支持该协议或配置的终端用 `Ctrl+C`（`\x03` / kitty `CSI 99;5u`），应用侧三种输入都已支持。
- 按键路由集中在 `input/`，组件内禁止散落按键判断。
- 交互反馈自然克制；不得因 hover、文案或 loading 改变既有布局尺寸。

## 尺寸与降级

- 最小可用尺寸 40x10，低于时显示尺寸提示并等待终端恢复。
- 宽度不足 80 列时隐藏左栏（右栏保留）；宽度充足时左右栏均可折叠为 4 列窄条。
- 窗格与右栏尺寸变化时同步更新终端网格与 PTY 窗口尺寸。
- 启动时启用 kitty 键盘协议（`DISAMBIGUATE_ESCAPE_CODES`），使 Super/Cmd 组合在支持的终端可达；不支持的终端忽略该私有序列，PTY 路径一律丢弃含 Super 的按键（防止 Cmd+C 漏成 `c`）。macOS 自带 Terminal.app 无法发送 Cmd 组合，只能使用 `Ctrl` 变体。
- 退出、panic、收到终止信号时必须还原鼠标指针形状、还原光标、关闭括号粘贴、清理全部鼠标上报模式、弹出键盘增强、恢复终端原始模式，并在等待在途上报后清空输入队列（防止鼠标序列泄漏进 shell）；恢复顺序为关闭鼠标上报 → drain 在途输入 → 弹出键盘增强 → 离开备用屏并关闭括号粘贴 → `disable_raw_mode()`，不可交换。

## 组件使用

- 优先复用 `ui/widgets/` 组件；确认没有可用组件后再新增，或直接组合 ratatui 原语。
- 无业务语义的组件不得依赖 `app` 领域数据。
- 菜单与模态容器是公共组件：`ui/widgets/menu.rs` 只接收锚点、标题与标签（定位/渲染/命中），`ui/widgets/modal.rs` 只负责居中、清底、边框、标题与按钮行布局，内容由调用方在返回的 inner 上自行绘制；`ui/widgets/scrollbar.rs` 只接收列表矩形与总量/视口/偏移（几何/命中/渲染）。三者均不依赖 `app` 领域数据。

## lx 聊天

- **步骤标记字形规则（硬规则）**：**文字数据用圆点，工具调用用方块，子 agent 主动汇报用上三角**。正文 `●`/`○`、思考 `●`/`○`、消息级通知 `●`；工具调用用 `■`/`□`（含合并的文件工具组标题、文件差异卡标题、委派卡片）；子 agent 主动汇报块用 `▲`/`△`（仅 `Subagent report`，不扩散到委派卡片或普通工具卡）。圆点表示「一段文字」，方块表示「一次真实动作」，上三角表示「子 agent 向主 agent 的汇报」。字形只在 `ui::text::agent::STEP_MARK_*` 定义，由 `StepMark::glyph(kind, loading_frame, animating)` 按 `StepKind` 选取，渲染层不得写死字符。
- **块间空行口径**：同一条消息内任意两块（正文 / 思考 / 单个工具卡 / **合并文件工具组** / 底部通知 / 统计行）之间**一律空一行**，消息与消息、消息与撤销提示/compact 检查点之间同样空一行。行数只由 `history::snapshot::build` 累加，`layout` / `render` / 命中都读同一份快照，禁止在绘制路径里另算空行。

- 首条消息前 lx 页沿用欢迎页（品牌区 + 三入口 + 输入框）；首条消息提交成功后内容区转为可滚动历史，输入框保留在底部（保留自身上下 `─` 分割线），状态（模型 · 上下文占用 + 其右侧运行指标）绘制在**窗格底边框**（`╰──╯`）上。初始页面与聊天模式都常驻显示该状态。
- **横向对齐**：输入框左右外边距为 1 列（`LX_INPUT_MARGIN`，比内容区各外扩 1 列），消息列表与状态都与输入框**同宽对齐**（列 = 输入框列）；消息列表右侧预留 1 列滚动条槽（`LX_HISTORY_SCROLLBAR`），其内容宽度再扣该列。- 历史按旧到新排 user/assistant 消息。用户消息首行 `> ` 前缀（图标用输入框同款强调色 [`style::accent`]），整块铺低饱和浅底色（`style::chat_user_bg`，跨行一致，覆盖图标列与滚动条槽之前的整宽）。assistant 消息不显示 `assistant` 标签，正文用共享阅读渲染器 `ui::markdown_render`（与 UI 页 agent 回答同款：标题/markdown 标记折叠、列表/引用/代码块/表格/行内样式，代码块做轻量语法高亮）。**markdown 渲染按可用宽度自适应**（参考 opencode，可用宽度已扣除步骤标记的 2 列缩进）：表格先按内容测列宽，若超出可用宽度则按比例收缩列宽（每列不低于其最宽字符宽）并在单元格内换行，方框网格绝不超宽/被硬折断；段落/列表/引用按词优先软换行（宽字符两列），超长不可断内容按列硬切。assistant STEP_BREATH_TICKS`，约 400ms 一相），终态停为静态标记；**动画停止时（`chat.status.streaming` 为假）恒画实心**（正文/思考试 `●`，工具调用试 `■`）；**终态（完成 / 失败 / 中断 / 取消）一律实心**，空心只属于运行中的呼吸相——相位冻结在空心那一相会让活着的步骤永久显示成「看起来失败」，取消画成空心也会被读成「还在跑」，这条兜底写在 `StepMark::glyph(kind, loading_frame, animating)` 里，不靠状态层在收尾时归零。配色按**步骤类别**分三档（`StepKind`：正文 / 思考 / 工具），另加终端默认前景的可变参数与 dim - 历史列表右侧常驻一列滚动条（复用 `ui/widgets/scrollbar.rs` 同一几何口径）：内容超出视口时显示（**只画 thumb `▐`；轨道不再绘制 `▕` 竖线**，占位列与命中几何保留），支持滚轮、左键轨道跳转与 thumb 拖拽；拖到底自动恢复跟随最新。滚轮按真实渲染行数与视口行数钳制（视口行数取 **body**——置顶行让位后的高度，与渲染同口径；不再用行数估算）。滚动条与轨道同样只覆盖 body。
- 状态（`模型名 · 上下文占用` + 其右侧 `N process · N subagents` 运行指标；**供应商名不再显示**，位置让给上下文占用）绘制在**窗格底边框**（`╰──╯`）上：运行指标仅在后台任务/子 agent 运行中显示，紧贴上下文占用右侧并用 ` · ` 分隔；模型名/上下文放不下时按原有降级链裁剪。只改写文字落到的单元格，两端角字符与其余底边线**保留为 `─`**（边框始终可见，不整段清空）。模型名用**入口标签同款粉→蓝渐变加粗**（`style::model_label_style` = Native 入口标签的 `218→117` 逐字符渐变，`selected` 态；端点固定用 Native，历史消息不存模式、不随当前模式变色；渐变按**可见**标签长度取样，硬切后的模型名同样跑完整渐变）；**供应商名不再显示**，紧跟模型名的是 ` · 当前用量(百分比)`（一位小数 token 短格式 + `(NN%)`，如 `258.7k(25%)`——**不带 `context:` 前缀**，紧跟模型名后语义已明确；百分比 = 用量 / 模型上限（四舍五入）、夹到 100%；整段用**次要信息色** `style::chat_provider` = `style::muted()`，默认前景 + dim、不加粗；**无上下文——未知上限、未知用量或零消耗——整段隐藏**，不再使用字符进度条）。**底边框上没有停止按钮**：流中按 `Esc` 单击待命、双击停止（见输入语义）。上下文分子按 codex 口径取最近一次同模型请求的**输入 + 输出**（`total_tokens`，下一轮请求输入近似），切模型立即更新上限并清空旧模型的分子；`/resume` 打开历史会话时从最近一条带用量的 assistant 轮次恢复该分子，重开不再显示空上下文。各控件矩形由同一布局函数（`status::layout(inner, status, tasks, subagents)`，绘制行 = `inner.bottom()`）派生，不随字符串长度改变。历史入口按钮移除，统一走 `/resume` 命令。**窄宽度降级**：运行指标优先于模型名保留；模型名在剩余宽度内硬切（编辑键 `Esc` 仍可中断），上下文占用放不下时整段隐藏；模型名按列**硬切**、上下文占用**不使用省略号**。
- 窄窗格长模型名一并截断（状态恒占底边框一行、不分行），不与输入框、命令面板或省略提示重叠；上下文裁剪省略提示贴底边框状态左侧区右端。
- `/model` 为两级面板：第一级候选展示**供应商名 / 模型名**（`ModelConfig.name` / `ProviderConfig.name`，不暴露配置里的 id），先选已启用且有 Key 的模型（选择与发送仍用稳定 id），再选该模型真实 `variants`；无 `variants` 直接使用默认值；第二级 `Enter` 采纳高亮等级并写入下一轮选择；`Esc` 从等级退回模型列表、再次 `Esc` 关闭。采纳后把该选择写回 `config/ai.json` 的 `defaultModel`（下次启动沿用此模型）。`/resume` 打开当前工作区历史（标题、状态与右侧相对时间），支持打开/编辑（改名、删除）；不跨工作区。`/new` 解绑当前窗格会话回空白草稿。面板优先级：粘贴参照、`@` 提及、markdown 块面板高于 `/`；同时最多可见一个面板，`Enter` 在面板打开时先采纳。
- **`/model`、`/resume` 的「当前已生效项」标记与视口定位**：两个二级面板都用行首 `❯`（`text::CURRENT_ITEM_MARKER`，与侧栏/列表同字形、同色规则）+ 与键盘高亮同款 `overlay_selection` 底色标出「当前已生效」——`/model` 是当前模型（第二级是当前 variant），`/resume` 是当前窗格已绑定的会话。标记列对全体条目占同一宽度（标记项 `❯ `、未标记项两个空格），名字左缘始终对齐；标记与键盘高亮叠加时底色只画一份、互不覆盖（"我现在用的是哪个"与"我下一步要采纳哪个"是两个独立提示）。打开面板时高亮与窗口都对准当前项（**当前模型取 `LxChat::effective_selection`**：窗格级选择缺失或失效时回落配置 `defaultModel`，保证重启后打开面板仍能标出并高亮当前生效的模型）：`PanelWindow::new(active)` 的锚点语义即**最小滚动**——当前项在候选靠后时贴底可见、靠前时贴顶可见、本来就在视口内则窗口完全不动。命令候选面板与空态占位没有该概念（不占标记列）。
- **`/resume` 会话编辑模态（`Shift+Enter`）**：`/resume` 二级面板打开时按 `Shift+Enter` 打开高亮会话的编辑模态（其余任何时候 `Shift+Enter` 仍是换行）；模态为全局浮层 `Overlay::ResumeSessionEdit`（居中、清底、强调色边框），内容为**标题单行输入**（预填当前标题，`> ` 前缀，硬件光标跟随）+ 底部按钮 `[save enter] [delete ^d] [cancel esc]`。`Enter` 保存（标题去空白后为空则拒绝：模态内红字提示、不关窗、不落库）、`^D` 进入删除确认、`Esc` 关闭；进入确认后按钮换成 `[confirm del enter] [cancel esc]` 并在输入行下方显示红字 `Press ^d again to confirm`，再按 `^D`/`Enter` 才真删，`Esc` 只是**退回编辑态**（不关窗、不删）；确认态不接受标题编辑。改名与删除都是异步落库，**成功回执后**才更新列表（失败保持列表原样），不做乐观更新。**改名只改 `title`、不刷新 `updated_at_ms`**（改备注不是对话活动，不该把该会话顶到"最近活动"最前）；改名成功后就地改该行标题、高亮不动；删除成功后该行消失、高亮顺位落到下一行（末尾则回退），`/resume` 面板**不关闭**，便于连续整理。删除正在被**其它窗格**运行中的会话时拒绝并在模态内显示 `Session busy`（本窗格自己的会话按既有语义先停流再删）。模态归属键（发起窗格 + 工作区 cwd）随打开固定，切工作区或切焦点窗格即作废并丢弃未保存标题（对齐引用文件夹弹窗的归属键口径）。
- **`/resume` 面板底边提示**：`[select ↵] [edit ⇧↵] [close esc]`——`⇧↵` 与 `@` 提及面板同一符号写法，明示会话编辑模态的入口（此前的底边漏了这一项，用户无从发现该快捷键）。
- **`/resume` 时间列**：条目右端右对齐显示相对时间（`just now` / `5m ago` / `3h ago` / `2d ago`；超过 7 天显示 `YYYY-MM-DD`），**不再显示会话 id**（id 仅内部绑定用）。时间基准是面板内的 `now_ms`，由事件循环每轮 `tick` 刷新——面板停留期间相对时间自然推进，而 `ui/` 仍只读状态做算术（不自己取系统时间，测试可固定该值断言边界）。未来时间戳（时钟回拨）按 `just now` 处理。
- **命令别名**：命令名之外可配别名，别名按精确/前缀命中同一命令（不做子串/子序列，避免 `/r` 之类误命中）：`/session`→`/resume`、`/clear`→`/new`。
- **markdown 表格**：方框网格每一条数据行之间都有水平分割线 `├─┼─┤`（表头之后、以及除末行外每条数据行之后；末行与下边框合并）；**第一列为空的行视为上一条目的续行**，其上方不画分割线，使同组多行视觉合并为一块（对齐 markdown「同组多行、首列留空」的常见写法）。单元格先做行内渲染（折叠 `**` 等标记）再按列宽换行，`<br>` / `<br/>` / `<br />` 换行成多物理行。
- **快捷键符号统一（全项目唯一规则）**：修饰键与「需要按下的键」用符号，动作词保留全拼。符号唯一来源是 `ui::text::key`（禁止在组件里另写字形）：Shift `⇧`、Enter `↵`（作为按键出现时）、Cmd `⌘`、Backspace `⌫`；Ctrl 保持 `^` 记法（`^c`/`^d`/`^z`，终端圈通用且已是既有统一写法）；`esc` 保留全拼（`⎋` 在部分终端字体缺字形，且 `esc` 已是既有的短记法）。因此：`@`/`/`/`/resume`/引用文件夹等面板底边、信任页提示写 `[open ⇧↵]`、`[select ↵]`；模态按钮写 `[save ↵] [create ↵] [confirm ↵] [confirm del ↵] [open ↵] [trust & open ↵]`；tooltip 写 `undo (^z)`。**禁止**再出现 `shift`/`ctrl`/`cmd`/`backspace`/`enter` 的全拼（动作词 `esc`/`cancel`/`close` 例外）。该规则由 `ui::text::tests::shortcut_symbols_are_single_width_non_pua_and_used_consistently` 与 `action_words_stay_spelled_out_while_keys_use_symbols` 守住（单宽、非私有区字形 + 提示文案不含全拼）。
- `/` 命令面板与 `@` 提及面板同款几何与交互：左右边缘对齐输入框、宽度充满输入框（内容更窄也强制等宽），底边紧贴输入框上沿，顶边 `Commands`/`Model`/`Reasoning level`/`Resume` 标题、底边 `[select ↵] [close esc]` 提示、候选右端 `[Built-in]` 来源标签；条目区最多 `MAX_POPUP_ROWS` 行并随可用空间收缩，溢出时面板内右缘显示滚动条。键盘 `↑`/`↓` 循环移动高亮并让窗口跟随；鼠标悬停只改高亮、不滚动窗口；滚轮滚动窗口而高亮不动；左键点击按 `Enter` 语义采纳。**命令候选面板打开时编辑键不被吞**（与 `@` 面板一致）：继续输入按模糊匹配（精确 > 前缀 > 子串 > 子序列，含别名）过滤、删除 `/` 即关闭面板；`Model`/`Resume` 二级面板仍吞编辑键。`/model` 无可用模型、`/resume` 无历史时显示单行空态占位（不可点选）。面板标题/提示/预览/标签与命令描述一律使用单宽（ASCII 或 `@` 面板同款单宽符号），禁止出现中文等双宽字符以免撑破布局。
- `Enter` 在无面板且 Native 空闲时发送、`Shift/Ctrl+Enter` 换行、`Esc` 在无面板且流中时**单击待命、窗口内（3 秒）再次按下才停止**（对齐 opencode：待命时输入框上方 loading 行把 `Working` 换成 `Press esc again to stop`，按宽度退化为 `esc again to stop` / `esc again: stop` / `esc stop`；超时或流结束清除待命）、`Ctrl+T` 折叠/展开 thinking；生成中 `Enter` 不重复发送、不新增消息。只有 Native Agent 可发送，Hybrid/Automation 显示不可用状态。
- 发送时本轮用户文本必须取**最近一条 user 消息**的正文 part（若只看 `messages.last()` 会取到紧随其后的 streaming assistant 占位，得到空串，导致请求携带空 user 消息被供应商以 `param: messages` 拒绝——表现为该轮历史永远停在流中状态）。异常退出遗留的 `streaming` assistant 行在启动时统一标记为 `interrupted`，恢复会话不再出现永久 `[streaming]`。
- 流式请求在**尚未产出任何内容**时对可重试故障（连接失败、超时、`429`、`5xx`）自动重试，最多 10 次、指数退避 2s→10s（约 84s 窗口，对齐 opencode 的 `exponential(2s)+spaced(10s)+recurs(10)`）；已有 partial 时不重试以免重复内容。**打字机**：每解析出一个网络分块的增量立刻经回调回投事件循环并即时渲染（内容随流实时增长），不等整段流结束；终态 `Finished` 在最后单独回投。失败消息在历史行以**底部通知**（`! Failed` + `└─ <码>`，见上）展示脱敏原因：状态码 + 截断限长（≤160 字符、单行、去控制字符）的错误体说明（如 `http 503 · upstream unavailable`），原因码随消息落库、重启后仍可见；错误说明不得含密钥（Key 只在请求 header）。
- `ui/` 只接收 `&AppState`（及只读派生），命中几何与绘制共享纯函数；不在渲染中读取数据库、配置文件或执行网络请求。历史增量以 buffer/geometry 测试覆盖宽/窄/极矮、中文宽字符、长模型名、折叠 thinking、在途流与用量未知；实际终端观感由用户 `cargo run` 确认。

## lx 本地命令（shell 模式）

- **进入与退出**：整段输入的**首个非空白字符**为 `!` 或全角 `！` 时进入 shell 模式；模式字符被吸收进模式字段（正文不含前缀），序列化时补回 ASCII `!`。正文中任意其它位置的 `！`、`¥`/`￥` 原样保留。键盘输入、整段粘贴与输入历史召回共用同一判定；只有光标在正文起点时按 `Backspace` 退出并保留正文，空命令按 `Esc`（无活动任务时）退出，`clear` 也可退出。undo/redo 恢复模式、正文与光标，修订号只增不减。
- **输入框外观**：Chat 仍为 `> `；Shell 用等宽 `!` 前缀（`style::shell_prompt`，浅红），输入框**高度不变**；`Shell mode` 提示写在输入框下边规则行右端，窄宽度先隐藏。队列非空时同一位置显示 `Shell mode · N queued` 或 `N queued`。shell 正文按原始脚本绘制，不做 Markdown 高亮，不弹 `@`/`/`/Markdown/路径参照面板。
- **提交语义**：Enter 始终立即执行（不受模型入口/Key/busy 限制），命令在冻结 cwd（工作区执行根）的登录 shell 中作为完整脚本执行，支持换行、引号、管道、`&&` 与重定向；空命令只给提示。DB 预登记成功后才 spawn；spawn 成功才把 `!命令` 写入全局输入历史并（修订号仍匹配时）清空草稿回到 Chat。DB 失败或 spawn 失败保留草稿、不记历史。
- **并发与队列**：本地命令不占用模型 `RequestState`；模型流与命令可同时运行。模型或命令忙时 shell `Tab` 把草稿加入 FIFO，空闲时 `Tab` 保留输入不执行。仅本地命令运行时普通聊天 Enter 冻结入队，命令终态且结果落库后按 FIFO 分派；模型结束也继续分派队列。切会话、`/new`、删除会话清空队列。
- **停止**：双 Esc 目标集合 = 模型在途轮次 ∪ 该窗格 pending/running 命令（含尚无进程 ID 的预登记命令）。第一次 Esc 待命（仅命令在跑时显示 toast），3 秒内第二次停止并清空队列；保留已产生的输出，不停止本轮未操作的后台服务。
- **命令卡片**：独立历史项，与工具步骤**共用直角树体语法**（`  │  ` / `  └─ `，5 列前缀）。标题是唯一不带连接符的行：`■ Running` / `■ You run command · exit 0 · 1.2s`（终态把退出码与耗时并入标题，窄屏只截断标题尾部）；树体首行是 `$ 命令`，其后是受控输出预览。参数区与输出区**各自独立折叠**：参数折叠 2 个物理行、输出折叠首 3 + 尾 2 行（各带 `… N more lines` 提示行），无输出时显示 `(no output)`；参数区恒为浅黄、不随 hover/展开变色（`… N more lines` 同色），输出区折叠 dim、展开为终端默认前景（没达到折叠额度时不登记点击面），不铺整行底色，标题始终为状态色。`└─` 只收口参数区（参数在图内），输出内容只用等宽空白对齐、不被树体包裹。命令运行中不铺实时输出，只给 `$ 命令` + `open task panel · live output` 一行引导（点击打开后台任务面板并定位该进程）。展开显示完整已保存输出（最多 64 KiB），拖拽复制不触发展开。输出按安全文本绘制并剥离控制序列；命令卡片不参与置顶用户消息行。
- **上下文**：只有终态记录进入模型上下文，格式为稳定的 `<user_shell_command>` 文本（脚本、状态、退出码、耗时、输出、截断信息；结构符号与输出均转义/净化）。历史回放与实时注入复用同一格式与按提交 sequence 的连续终态前缀；一次请求内按稳定消息 ID 去重，注入总量有界，不新增模型工具调用或 token 统计。

## rtk 输出压缩（agent 与本地命令共用）

- 目标：命令输出进入模型上下文前先压缩，降低 token；不改变命令语义、退出码与真实输出偏移。
- **后端选择**：`LX_RTK_MODE` 控制 `auto`（默认：优先外部 rtk，缺失时内置）、`builtin`（强制内置）、`off`（关闭）；`LX_RTK_BIN` 可显式指定 rtk 可执行文件。测试构建默认 `off`，避免开发机是否安装 rtk 影响断言。
- **外部 rtk**：仅当命令首段是受支持的短时工具时才前缀 `rtk`（`cargo build/test/check/clippy/install/nextest`、`git diff/log/status/show/add/commit/push/pull/branch/fetch/stash/worktree`、`ls/tree/grep/rg/find/wc/diff/gh/glab/aws/psql/dotnet/jest/vitest/prisma/tsc/prettier/playwright/curl/wget`、`npm|pnpm test`、`npx tsc|eslint|prisma`）。带前导赋值、`cd &&`、换行、已带 rtk 或长驻/交互形态的命令不包装，避免把流式输出改成结束才返回。
- **内置兜底**：未包装或没有外部 rtk 时，按命令类别过滤（测试只留失败/摘要；构建去掉编译进度、保留警告/错误块；git status 限制文件数；diff 只留增删与 hunk 头；grep/rg 按文件与总量限制；ls/tree/find 限制行数；通用输出保留首尾并按字符兜底）。所有裁剪都写入显式省略标记，绝不静默丢数据。
- **归属**：模型 `exec_command` 由执行器在 spawn 前包装、返回结果前内置过滤；`!` 本地命令在事件层预登记后同样处理。卡片与上下文里的 `command` 始终是用户原始命令，包装只存在于实际执行的脚本。
