## 1. 问题与成功标准

当前补充块把起始标记、标题、分隔行、正文、底部留白与结束标记逐行放在父任务中。补充内容增加时，任务正文被大量补充说明隔开；即使减少空行，也无法解决几十个长补充块占满视口的问题。

目标是把补充块作为当前任务的附件集中管理，任务正文只显示一个紧凑入口，选择附件后在独立区域查看和编辑全文。附件在这里是界面概念，不意味着磁盘文件或新的持久化实体。

验收时以同一个父任务内 1、20、100 个有效补充块比较：

- 未打开附件管理时，同一任务的附件入口固定占一行，不随附件数量线性增加。
- 可以访问并编辑每个附件，列表溢出可以滚动，不截断为只能访问前几项。
- 从附件视图返回后，任务正文的位置与编辑历史可解释，不跳到无关任务。
- 单纯打开、浏览、关闭附件，不改变原文，不触发脏状态。
- 编辑结果只更新目标补充块，其他任务、补充块和块外文字不变。
- 已有提示词不需要迁移；格式错误的块不被静默隐藏而失去修复入口。

## 4. 方案比较

| 方案 | 对长正文的压缩效果 | 查找与编辑 | 取舍 |
| --- | --- | --- | --- |
| 仅减少空行、合并标题与边框 | 只省结构行，正文仍完整占位 | 最接近现有方式 | 无法解决大量长补充块，不能作为主方案 |
| 每个子块折叠为一行 | 每个补充块仍占一行，20 个即 20 行 | 单项展开直观 | 可作为比较项，不是已选择的主方案 |
| 横向并排排列多个完整子块 | 高度减少但争抢宽度 | 宽终端尚可 | Prompt 常为窄侧栏，不宜默认采用 |
| 在原正文位置分页显示子块 | 可限制当前可见数量 | 需要翻页才能找到内容 | 正文与附件边界仍混杂，页切换还会改变正文位置 |
| 集中附件栏 + 独立编辑 | 每个任务一个入口；内容多寡不撑高任务正文 | 列表定位后独立查看、编辑 | 已选；需要统一坐标映射、目标校验与返回行为 |

附件列表仍然随数量增长，但增长被限制在独立的可滚动列表内；不能把列表完整插回任务正文后宣称解决了高度问题。

## 5. 信息组织与高度口径

概念示意；英文仅用于说明最终 TUI 文案方向，实际文案须进入 `src/ui/text.rs`：

```text
任务正文视图                         独立附件区域
┌ Task A ─────────────────┐          ┌ Supplements · Task A ─────────┐
│ title: Repair login     │          │  1  API requirements          │
│ ...任务正文...          │   打开   │  2  Test cases                │
│ Supplements · 20 [open] │ ──────→ │  3  Error examples            │
└─────────────────────────┘          │ ...列表独立滚动...            │
                                    └───────────────────────────────┘
```

入口固定在父任务末尾、结束边框之前。原文中块的位置和顺序保持不变；界面上的集中显示不执行文本搬迁。没有安全可附件化子块的父任务不显示空入口。

隐藏子块时还要在显示投影中收敛与该隐藏区直接相邻的纯空白间隔：连续的隐藏子块和它们之间的空行整体不占位；如果隐藏区两侧都有可见正文，保留最多一行段落间隔。其余用户正文空行不全局清理，原文与持久化内容均不改变。否则 20 个隐藏子块仍留下 20 组空行，无法达到减少占位的目标。

“固定一行”指每个父任务的附件管理入口，而不是把用户真实正文强行压到固定高度。附件之间若原来穿插普通正文，这些普通正文继续可见，不挪动、不删除；仅附件本体和附属空白的开销不随附件正文长度增长。

列表按原文出现顺序生成。标题优先使用现有标题语法，空标题使用 `Supplement N` 兜底；重名用序号区分，不以标题作为身份。显示时按终端列宽截断，不能按 UTF-8 字节截断中文。当前项、鼠标悬停与键盘焦点必须可辨认。

## 6. 数据与坐标模型

### 6.1 单一正文来源

持久化仍只保存现有 Prompt 原文。附件索引是派生数据，不新增数据库表、外部附件文件、序列化格式或强制块 ID。

建议派生项包含父块范围、子块范围、标题和显示序号。范围必须明确单位：解析结果是逻辑行范围，编辑使用 UTF-8 字节范围，鼠标使用屏幕格坐标，三者不可混用。

不能缓存一个子块行号就长期使用。插入或删除前面的文字后，行号和字节偏移都可能失效；需要根据当前修订重新生成索引。

### 6.2 正文展示投影

原文保留全部内容，任务正文视图使用显示投影：有效补充块不逐行显示，改由父任务的单个合成入口代表。真实文本行与合成入口必须使用可区分的数据结构。

建议的数据形状，仅表达约束，不是已存在或已批准的 API：

```rust
enum PromptDisplayRow {
    Text { source_row: usize },
    Supplements { parent_start_line: usize, count: usize },
}
```

`source_row` 指向原来的软换行结果；合成行没有可直接编辑的原文字节。所有行高统计、滚动条、绘制、光标、鼠标定位和选区操作必须共享这份映射。不能渲染按投影、点击却仍按原文第 N 行取偏移。

跨附件写入保护见 §6.7，原文入口见 §6.8，可见复制见 §6.9；导航、空白和焦点的具体投影契约见 §11。实现必须同时满足，不能各自维护不一致的行序。

### 6.3 编辑会话归属

保存目标至少需要：正在显示的 Prompt 所属工作区、条目或临时提示词身份、页身份、父任务与子块范围、打开时的修订信息。不能只取当前活动工作区；钉住的 Prompt 可能属于别的工作区。

保存前验证文档身份、修订和目标原文均匹配，再进行局部更新；失配时保留编辑草稿并说明目标已变化，拒绝把内容写进另一个附件。保存策略见 §6.5，具体状态建议见 §12。

进一步核实的现成身份能力：`Prompt::id()` 返回 `PaneId`；`AppState::prompt_workspace()` 考虑钉住归属；`PromptEditing::{Item(i64), Temp(u64)}` 区分编辑目标，`PromptPageId::{Saved(i64), Temp(u64)}` 区分页。工作区索引会随重排变化，不能单独作为稳定身份。

特别注意：`set_text` 和 `restore_history` 替换文本但不增加 revision。保存校验必须组合编辑器身份、目标、页、修订与原区间文本；单独比较 revision 不足以防串写。切页入口 `select_prompt_page` 已先收束旧页与面板，是未来附件编辑生命周期需要接入的节点。

### 6.4 已核实的坐标风险

`src/app/prompt/viewport.rs` 的 `visual_rows` 同时被 `cursor_cell`、`cursor_visual_in`、`content_offset_at`、`selection_bounds` 和 `scroll_cursor_into_view` 使用；上下移动、Home/End、块按钮与 `src/ui/prompt_frame.rs` 的滚动条也依赖此行序。

`selection_bounds` 把选区首末坐标转为原文连续区间。只隐藏补充块行时，跨附件拖选仍会包含隐藏原文，随后删除会连附件一起删除。这必须通过明确的选区契约解决，不能仅靠样式掩盖。

`cursor_visual_in` 的既有定位假定光标属于连续显示的文本；过滤掉原文区间而不归一光标，可能出现光标早于下一行起点的反向切片。投影变更必须同时审计所有光标落点，保持字符边界和行内区间合法，不可只给 `visual_rows` 添加过滤器。

这些是实施前必须解决的正确性问题，不是可留到界面验收时再补的外观细节。

### 6.5 已确认：独立草稿与明确提交

用户已通过问题 3 确认此策略。打开附件时复制其可编辑内容到本地草稿；输入只修改草稿，父 Prompt 原文保持原样。用户明确保存时，校验归属和原文，再把对应完整非空子块作为一个局部替换提交，父 Prompt 形成一条撤销记录。

“保存”首先表示更新父 Prompt 缓冲区，随后沿用父 Prompt 已有的持久化机制，不能把本地替换成功直接显示成数据库落盘成功。草稿本地撤销与父 Prompt 撤销分开；保存后的父撤销按一次提交恢复整个附件改动。

无修改关闭直接返回；有修改退出时提供保存、放弃或继续编辑。编辑页不提供绕过草稿结算直接切到另一附件的路径：先返回列表，再打开另一项。界面上的 `Esc` 先服从当前候选面板的既有关闭优先级，再处理编辑区退出，不能抢占 `@` 或格式候选的关闭键。完整操作表见 §11。

提交保留未编辑的起止标记、命令名与 `{wt:}` 等结构；如选用复用 `Prompt` 作为草稿编辑器，需要保留正确的补充块上下文，不能把裸正文当普通文档导致命令候选变化。`settle` 会重算候选面板，保存返回后也要按最终规则收束临时面板，避免突然弹出无关候选。

### 6.6 已确认：居中大弹窗内切换列表与编辑

用户已通过问题 4 确认：打开附件入口后，使用居中大模态展示当前任务的附件列表；打开某项后在同一个模态内切换为全文编辑，返回列表保留原选中项和滚动位置。无需左右并排，也不在列表上继续叠加第二个编辑弹窗。关闭整个模态后回到父任务。

理由：Prompt 本身常为窄侧栏，直接在侧栏中编辑长补充说明仍然拥挤。模态的可用空间以整个终端为准，复用 `src/ui/widgets/modal.rs` 的 `layout(screen, width, height)`、`ModalShell` 与清底/边框渲染；该布局已把请求尺寸钳制到屏幕范围。尺寸与极小屏策略见 §11，不把通用容器宽 4 / 高 3 的最低绘制条件当成可编辑条件。

概念流程为：任务入口 → 附件列表 → 单项草稿编辑 → 保存或处理未保存修改 → 返回列表 → 返回任务。弹窗不让键鼠穿透到底层；顶部关闭按钮与 `Esc` 都必须服从已确认的未保存退出策略。

### 6.7 已确认：普通正文编辑保护隐藏附件

用户已通过问题 5 确认：集中展示模式下，普通正文的删除、剪切、选区替换、粘贴替换等操作，只要原文作用区间与隐藏附件相交，就整体拒绝本次修改，并给出可见提示。原文和撤销栈保持不变，不进行只删除一半的隐式处理。剪切被拒绝时也不改写剪贴板，避免出现“内容已剪切”的假象。

原因是附件的集中位置与其原文位置不同。界面上选中了两段相邻正文，原文中间可能夹着一个完整 `+++`；不能把可见选择的两端直接当成连续原文区间执行删除。

明确的附件管理删除与既有“删除整个父任务”是领域操作，可按其原有边界删除相应附件；普通编辑不能冒充这些动作。原文模式全部可见，沿用既有全文编辑规则，见 §6.8。

需要覆盖所有可写入口，不能只保护 Backspace：选区删除、输入字符替换、粘贴替换、删词、删到行首尾、整行操作等都要经过相同的相交判断。零长度插入如果落在隐藏区内部也应拒绝或先重新定位，禁止把用户输入塞进看不见的附件。正常的可见文本编辑保持原有行为。

此保护不扩展为多区间编辑；要批量调整附件与正文结构时使用已确认保留的原文模式。

### 6.8 已确认：保留显式原文编辑模式

用户已通过问题 6 确认保留：默认使用集中附件视图，同时提供明确的“原文”切换入口。原文模式完整显示同一份 Prompt 文本，包含 `&&&` 和 `+++`，允许按现有编辑规则调整结构、移动块和修复格式；返回集中视图时重新解析。

它与 Prompt 当前的树/编辑视图切换是不同维度。现有 `PromptToolbarButton::Mode` 负责树与编辑，不应改造成原文切换导致旧入口失效。原文切换使用独立动作与按钮，窄宽度下仍可按 `F4`，见 §11。

原文模式不复制正文、不清空历史、不调用 `set_text`，只是改变同一编辑器的展示方式；切换本身不生成撤销记录或脏状态。集中模式的隐藏范围保护仅作用于不可见附件；原文模式附件已完整可见，恢复既有全文编辑规则，但既有标题和 worktree 结构保护继续生效。

附件弹窗打开时不直接切换底层模式；需要先按已确认的保存/放弃/继续编辑策略收束草稿。切换模式时清理基于旧行序的屏幕选区，保留合法原文字节光标；返回集中视图若光标落在附件内部，转为聚焦该父任务的附件入口并保证其可见，见 §11。

举例：想把第三份补充说明移到第一份之前，或修复手写的结束标记时，进入原文模式操作；日常填写内容仍用附件弹窗。

### 6.9 已确认：选区复制只复制可见正文

用户已通过问题 7 确认：集中视图中，拖选或全选后的复制只提取被选中的可见原文，排除隐藏附件及 `Supplements · N [open]` 等合成界面文案。可见段落按原文顺序拼接，保留被选中的真实换行；软换行不额外插入换行，移除隐藏区后至少保留必要的段落分隔，不能把附件前后两个词意外粘连。

完整提示词复制动作与原文模式的选区复制继续按原文处理；无选区复制全文的已有语义也保留。附件自身正文从附件编辑区或列表的复制动作获取。此区别要在最终操作表中标清楚。

已核实 `src/app/update/selection.rs` 的 `prompt_copy_text` 先调用 `prompt_selection_text`，后者返回 None 时回落全文。这意味着“只选中了合成入口”不能直接当成无选区，否则会把整页含全部隐藏附件复制出去。实现需区分无选区、有选区但没有可复制文字、有可复制选区，空文字选区不更改剪贴板，也不显示复制成功。

复制多段可见文字是只读投影；删除或替换仍遵循 D6 的相交拒绝，不因此引入多区间写入。原有 `selection_bounds` 的单个连续原文范围不能同时代表这两类操作，必须分别表达复制片段与写入范围是否合法。

### 6.10 已确认：附件删除先确认，提交后可撤销

用户已通过问题 8 确认：附件列表中的删除动作先在同一个模态内切换为确认状态，显示附件标题与序号；取消不改原文，确认才删除完整目标块。删除成功保留列表，选中下一项，删除末项则回退上一项；删除最后一项后显示空态和新增入口。

复用 `src/app/prompt/block.rs` 的 `delete_supple_block` 语义：包含起止标记，最多吸收一侧空行，`break_group → record(EditKind::Other) → replace_span`，形成一条父 Prompt 撤销记录。实际调用前必须重新验证目标身份、修订与范围，不能只把旧起始行号传给这个接口。

确认状态不再叠加新模态；`Esc` 回列表，不穿透关闭底层任务。附件编辑草稿未收束时不提供直接删除路径，先回到列表并按 D4 处理未保存内容。删除只改父 Prompt 缓冲区，后续保存走现有持久化机制，不操作磁盘文件或数据库附件表。

### 6.11 待最终审核的工程默认：新增与清理

新增入口放在附件列表的明确动作项中；先创建本地草稿，用户保存时才在父任务结束标记前插入完整补充块。取消新建不改变附件数、不留下空壳、不生成父撤销记录。新建保存同样校验父任务身份与打开时原文；不以保存时光标所在任务作为插入目标。

## 7. 已有关键代码与复用限制

现有 `Prompt::replace_range` 的关键行为如下（真实代码，非新增实现）：

```rust
pub fn replace_range(&mut self, start: usize, end: usize, insert: &str) -> bool {
    if start >= end || end > self.text.len() {
        return false;
    }
    if self.protected_edit(start, end) {
        return false;
    }
    let sanitized = sanitize(insert);
    self.break_group();
    self.record(EditKind::Insert);
    self.text.replace_range(start..end, &sanitized);
    self.cursor = start + sanitized.len();
    self.settle();
    true
}
```

因此实现前必须处理：

1. 区间两端必须是当前文本的合法 UTF-8 字符边界。
2. 空正文插入的 `start == end` 不适用这个接口，不能直接当作成功。
3. 结构保护可能拒绝替换；必须先设计保留起止标记、标题、绑定行的更新边界。
4. `true` 不应被直接当作“有实际变化”；相同内容保存应在调用前判断，避免制造空撤销和脏状态。
5. 保存后主编辑器光标落点需转到可见文本或附件入口，不能留在被隐藏的子块末尾。
6. 原始函数会净化输入，不能声称任意输入都逐字保留；沿用项目现有换行、制表符和控制字符策略。
7. `record(EditKind::Insert)` 会留下连续输入分组，保存后紧接着的普通输入可能被合并；附件保存必须使用 `EditKind::Other`，使提交前后的普通输入均与它隔离。

因此附件保存使用 `app/prompt` 内最小的领域提交入口，参照现有 `replace_block_body` 的 Other 分组和 `replace_span`，不通过 `set_text` 模拟保存。正文为空、新建插入、更新和删除由同一个已校验的局部提交机制处理，不修改全局 `replace_range` 的空区间契约来兼容单一功能。

下面是拟新增领域入口的核心伪代码，不是当前 API；`verify_target` 必须包含 §12 的全部校验，返回值应区分未变化与拒绝：

```rust
let target = verify_target(owner, revision, original_block, current_text)?;
let replacement = validate_supplement_draft(draft, &target)?;
if current_text[target.range.clone()] == replacement {
    return Ok(CommitOutcome::Unchanged);
}
self.break_group();
self.record(EditKind::Other);
self.replace_span(target.range.start, target.range.end, &replacement);
// 重新解析后恢复可见焦点，压制保存引起的候选面板重弹。
Ok(CommitOutcome::Changed)
```

`replace_span` 负责按文本区间平移父编辑器的原文光标，但不做安全校验。新领域入口需要验证 UTF-8 边界、合法父子关系与原文快照；保留起止行、命令名、结束行扩展字段及未编辑的 worktree 元数据，不能因为绕过普通编辑保护就任意覆盖结构。

### 11.3 可见复制的确定算法

投影保留各个 Text 行的原文字节区间；选区归一后分别裁剪首末行，按原文顺序汇总片段，软换行之间直接连接。跨原始逻辑行保留原文换行；跨过被隐藏的完整块时，只为两侧真实可见文本保留一个段落分隔，不复制隐藏块残留的多余空行。仅选中合成入口得到“已选择但无可复制文本”，不进入全文回退。

主模式的选区替换另行检查其原文覆盖区间是否穿过隐藏块，命中则拒绝。复制与写入不得共用一个返回 `Option<(usize, usize)>` 就假定语义一致。

| --- | --- | --- |
| `PromptPresentation` | `Compact` / `Source` | 内存展示偏好；工作区草稿挂起时随 Prompt 保存，不进 DB、默认 Compact |
| `PromptFocus` | `Text` / `Supplements { parent_start }` | 纯展示焦点；文本变化后校验或重新归一 |
| `SupplementIndex` | 父任务范围、子块范围、UTF-8 字节区间、标题、原文顺序 | 从当前文本派生，不持久化 |
| `SupplementOwner` | Prompt PaneId、工作区归属路径键、编辑目标可选值、页 ID 可选值、上下文 root | 打开附件时冻结；无条目的工作区草稿同样可打开，不能强制要求 DB id |
| `SupplementTarget` | owner、revision、父范围/原文快照、子范围/原文快照 | 当前编辑或确认删除目标；不把显示序号当稳定身份 |
| `SupplementView` | List / Edit / Unsaved / ConfirmDelete | 同一个领域模态的状态；不嵌套多个全局 overlay |
| `SupplementDraft` | 编辑缓冲、基线内容、新建/已有、待执行离开意图 | 只在内存中；dirty 按基线比较，本地 undo 后恢复原内容即 clean |
| 列表视口 | selected、scroll/window、hover | 返回列表保留；删除后按新列表钳制 |

主 Prompt 不应直接持有包含另一个 Prompt 的模态状态，否则形成递归所有权。模态会话挂在现有 `Overlay` 领域变体或独立的 app 会话类型中，编辑缓冲复用 Prompt 时是同级拥有关系；状态定义放 `app`，渲染放 `ui`。

`PromptHistory` / `EditorStash` 已按目标、页与正文匹配恢复原文字节光标和历史。展示模式放在 Prompt，同时纳入仅用于视图往返的 PromptHistory；不放进文本撤销 Snapshot，避免撤销文字时切换模式。加载新目标的 `set_text` 重置为 Compact，恢复同目标历史后按投影归一光标。展示焦点不依赖永久块 ID，正文修改后必须用当前索引验证。

草稿编辑可复用 Prompt，但裸 `+++` 文本在现有解析器里没有父任务上下文。采用最小只读父壳包住子块，构造可解析的 scratch 文本；编辑范围严格限制在该子块的标题值与正文，元数据走已有明确操作。父壳只供解析上下文，不显示、不提交。保存时提取并校验唯一目标子块，不把父壳写进原 Prompt。此能力留在附件领域模块，不扩展成通用多文档框架。

scratch 固定为 Source，不提供模式切换，其展示模式独立于父 Prompt。scratch 只裁切父壳和只读结构，不运行附件压缩；否则合法父壳中的子块会再次变成一个附件入口，正在编辑的正文反而消失。正文的显示、光标与选区均基于这个固定的局部 Source 视口。

保存顺序必须是：

1. 验证当前显示的 Prompt 所属身份、页与上下文 root；单纯活动 workspace 索引不能作为目标。
2. 比较打开时 revision，并逐字比较父/子原文快照；目标被重新载入或变化时拒绝提交，不做猜测式重定位。
3. 校验字节边界、闭合父子关系与只读元数据保留；草稿不能注入父结束标记、额外同级补充块等改变所属结构的内容，围栏内示例按已有解析处理。已有块保留原起止行，不用生成器重建导致 `{id:}` / `{wt:}` 丢失；新增块才用既有生成器产生配对外壳。
4. 原文未变化则返回 Unchanged，不入历史、不置脏；新建取消同样不改父文本。
5. 以 `Other` 历史分组局部提交，更新父 revision，刷新派生投影与列表；清理旧屏幕选区和候选，归一可见焦点。
6. 继续走父 Prompt 的既有自动/手动保存机制；持久化失败仍按原机制保留 dirty 和错误，不把缓冲提交描述成落盘完成。

目标失效时保持草稿并显示 `Target changed; copy draft and reopen`；允许复制草稿和放弃，不自动覆盖，不无限重试。父身份被强制移除时同样保留可复制的草稿快照至用户关闭；正常切页、切条目和切显示中工作区的动作在模态活跃时被消费或先收束，不能默默换掉底层文本。后台过期扫描与粘贴回执按 scratch 编辑器独立身份过滤，不套用父 Prompt 的旧请求。

解析兼容性以统一 `block_scan` 为准，不单独用缺少围栏上下文的旧父块扫描器建立附件索引。`parse_supple_start_line` 已通过 `SUPPLE_RESERVED` 排除 `log` / `logTemplate`。现有统一扫描并不要求起止 command 名相等，本任务不新增全局配对规则，也不因此拒绝旧块浏览或保存；已有边界行原样保留。元数据保护需要领域提交显式核对：`+++` 标题并不等于现有只扫描 `&&&` 的标题保护，结束行内 id/wt 也不等于独立 `{wt:}` 绑定行保护。

## 13. 数据流、成本与明确不做的事项

数据流：原文 → 现有块扫描 → 安全子块索引与显示投影 → UI 只读绘制与同口径命中 → app 打开模态 → 本地草稿编辑 → owner/原文校验 → 局部 Other 提交 → 原有持久化出箱。

按一次文本扫描构造逻辑行起点、父子归属和索引，按全文字节长度加视觉行数线性处理。不能对每个附件再次调用全文 `block_at` 或在每个单元格扫描全文。基于现有渲染调用方式在一次布局/绘制周期内复用派生结果；只有证据显示需要时再引入跨帧缓存。若缓存，键必须包括文本载入代次/内容身份、revision、宽度、展示模式；revision 单独不足以区分加载的新文本。

仅按选中的一份附件建立编辑草稿，不为列表所有项建立编辑器和撤销栈。100 项用于边界与索引验证，不代表只允许 100 项；本期不新增附件数量限制，也不引入后台线程或新依赖。列表总数与可访问数量必须一致。

本期不做附件搜索、拖拽排序、独立文件上传、批量编辑/删除、附件启用开关或 AI 自动总结。调整顺序和复杂批处理使用原文模式。界面不添加动画；键盘与列表切换即时反馈，保持现有 TUI 风格。

## 15. 具体验收样例

1. 构造三个父任务：第一个无附件，第二个 20 个各 50 行的附件，第三个只有普通正文。第二个只增加一个附件入口，第三个可以直接滚动访问；完整原文长度保持不变。
2. 在 20 项列表打开第 15 项，改标题和一行正文，保存后列表仍定位第 15 项；返回父任务后撤销一次恢复整份修改，再重做恢复；保存后额外输入的文字必须是另一步撤销。
3. 文本 A 与 B 之间插入一份子块。集中模式框选 A、B 复制不带子块；删除、字符替换、粘贴替换均提示并保持原文、剪贴板和历史不变。
4. 只选择附件入口后复制，剪贴板不被整个 Prompt 覆盖；无选区使用原有完整复制时仍保留所有 `+++`。
5. 新建草稿取消时入口计数不增加；保存后计数加一；删除先取消、后确认，确认后计数减一，主编辑器撤销恢复。
6. 原文模式修改起止标记导致子块不闭合，返回集中模式后错误区仍可见，不能把后一个任务吞进附件列表。
7. 切换同页不同 Prompt、同 Prompt 不同页、钉住后切活动工作区、加载文本但 revision 相同，均不把旧草稿写错目标。
8. 在 120×40、80×24、40×12、31×9 及恢复放大后检查模态、入口、滚动条、中文标题和空正文；过小尺寸不丢草稿、不修改底层输入。
9. 保存父 Prompt 后重启，从同一原文恢复全部附件及顺序；展示模式可以回默认 Compact，不要求持久化视图偏好。
