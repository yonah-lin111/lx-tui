# lx 输入框 `@` 文件命令面板设计

状态：待用户审核。本文和同目录 `task.md` 获明确批准前，不修改功能代码。

## 1. 目标与验收口径

在每个 lx pane 的多行输入框中输入有效的 `@` 查询时，显示该 pane 自己的文件/文件夹候选。面板紧贴输入框上沿，左边缘与输入框左边缘一致，外框宽度与输入框一致。候选根是该 pane 的终端当前路径；lx pane 的底部外边框左侧同时显示这一有效路径。路径、候选和面板状态都不跨 pane 串用。

完成后应能从一个 pane 的 lx 输入框键入 `@`，浏览、筛选、选择当前终端目录内的文件或目录；切到另一 pane 后看到另一套路径和候选；在终端视图执行 `cd` 并返回 lx 时，旧目录候选不能被采纳。长路径和窄 pane 不得破坏外边框，也不得改变输入框宽度。

## 2. 已确认的产品决策

| 编号 | 决策 | 具体行为 |
| --- | --- | --- |
| D1 | 候选写入 | 选择文件或文件夹写入相对扫描根的 `@路径`，使用现有 prompt 的提及插入规则；确认后关闭面板。例：`/work/demo` 下选 `src/main.rs` 得 `@src/main.rs `。 |
| D2 | 路径来源 | `pane.cwd` 优先；尚未轮询到时用该 pane 所属 `workspace.cwd`；轮询失败保留最后一次有效 `pane.cwd`。两者均无时无扫描根。 |
| D3 | 空查询 | 输入有效的 `@` 后立即列出当前目录候选，继续输入只过滤候选。 |
| D4 | 文件夹键位 | `Enter` 采纳文件夹并关闭；`Shift+Enter` 对有子项的文件夹进入该目录，写回 `@目录/` 并保持面板。面板关闭时 `Shift+Enter` 继续换行。 |
| D5 | 底边路径 | 只在 pane 的 lx 视图显示；完整路径放不下改最后目录名；最后目录名仍放不下时按终端列宽截断并加 `…`。不覆盖左右角。 |
| D6 | 路径切换 | 有效扫描根变更立即作废旧候选与在途结果；若光标仍在有效 `@` 查询中，保留查询文本并按新根重扫。 |
| D7 | 鼠标 | 点击候选等同 `Enter`；鼠标滚轮在面板内只滚动候选，不滚动 lx 输入框。 |

`@` 语法、候选排序、扫描忽略策略和相对路径插入格式优先复用 lx 现有 prompt 的能力；只借鉴 codex-main 的上方浮层位置与输入框等宽原则。codex-main 当前 `FileSearchPopup` 对单独 `@` 显示提示，且候选主要是文件；D3/D4 明确要求 lx 在这里采用本项目 prompt 的文件/目录行为。

## 3. 现状与依据

### 3.1 lx 代码关系

- `src/app/state/pane.rs`：每个 `Pane` 含独立 `Lx`、`cwd: Option<PathBuf>` 与 `cwd_label`；启动时 `cwd` 为空。
- `src/event/session.rs::poll_process_cwds`：PTY 输出后去抖约 300 ms，按 shell PID 查询 cwd，调用 `update_pane_cwd`；无法查询时原值不变。PTY 启动目录来自 `workspace_cwd_for_pane`。
- `src/app/state.rs::workspace_cwd_for_pane`：按 pane id 找所属工作区路径，允许跨非活动 tab 定位。
- `src/app/state/lx.rs`：`Lx` 保存输入、光标、撤销/重做、块命令面板和粘贴面板。`refresh_panel` 按当前文本与光标重建块面板。
- `src/input/mod.rs::lx_input_key` 把 `Shift+Enter` 映射为 `LxInput::Newline`。`src/app/update/pane.rs::apply_lx_input` 负责 lx 按键优先级，目前粘贴面板优先于块命令面板。
- `src/ui/main_content/lx.rs::layout` 计算输入框 `Rect`，现有块命令面板就在输入框上方；`render_paste_panel` 也绘制于该区域。`src/ui/panes.rs` 绘制 pane 外框，底边尚无路径内容。
- `src/event/mouse/press.rs` 当前把 lx 的非输入命中落到整页文本选择；`src/event/mouse/wheel.rs` 当前把 lx 上滚轮交给输入视口。新面板命中必须排在二者之前。
- `src/app/markdown.rs` 提供 `mention_trigger`、`filter_mentions`、`mention_insertion`；`src/files.rs::scan` 是已有异步可调用的文件/目录扫描函数。prompt 的提及面板已有目录范围、筛选、滚动和过期结果防护。

### 3.2 codex-main 参考

- `codex-rs/tui/src/bottom_pane/chat_composer.rs`：浮层矩形以 composer 的 `x`、`width` 为准，`y` 位于 composer 顶边上方；超出可用高度时缩高。
- `codex-rs/tui/src/bottom_pane/file_search_popup.rs`：结果使用相对搜索目录的路径；候选宽度不足时优先保留文件名；异步搜索结果按查询代号防旧结果回写。
- 本功能不引入 codex-main 的 composer、文件搜索 crate、插件/skill 候选或其它依赖。

### 3.3 检索与服务状态

已使用 codegraph 查询 lx 的 pane/Lx/输入/渲染依赖，并对 codex-main 建立 codegraph 索引（6,332 个文件），随后查询其面板与 composer 的关系。已尝试 codebase memory 的 `list_projects`、`index_repository`、`index_status`、`search_graph`，服务均返回 `Transport closed`；因此其图关系目前无法取得。实施前重试；若服务仍不可用，以 codegraph 与源码/测试核对，不伪称完成 codebase memory 分析。

## 4. 数据模型和不变量

每个 `Lx` 拥有自己的提及面板状态：当前根、扫描缓存、查询触发区间、候选、高亮、视口、扫描代号及在途标记。不要建立全局单例候选，也不要借用右侧 prompt 的 `MentionState`，因为它带有 prompt 专属的 worktree 绑定与选择器状态。

根路径由事件/更新层从 pane 与工作区计算后传入 `Lx` 的纯状态方法。`app/` 只存 `PathBuf` 和扫描结果，不扫描文件、不读进程、不发异步任务。候选路径始终相对本次扫描根，不能在根变化后沿用。建议将提及状态放在 `src/app/state/lx/mention.rs`；如果经实际改动发现文件长度/职责允许，也可收在现有 `lx.rs`，但保持单文件低于 1000 行。

必须保持以下不变量：

1. 同一 lx pane 中，块命令、粘贴参照和 `@` 提及至多一个可见；粘贴参照优先级最高，避免占位编辑被其它面板抢键。
2. 提及面板的触发区间位于 UTF-8 字符边界，确认和目录进入只替换当前有效触发区间；失效时只关闭面板，不改文本。
3. 异步结果同时匹配 pane id、扫描代号与当前根才可采纳；关闭 pane、切 tab、变根或新一轮扫描不能误写其它 pane。
4. 当前有效根唯一决定候选扫描和底边路径显示；路径值保留 `PathBuf`，仅渲染时转为显示文本。
5. `Esc` 关闭当前提及面板但保留 `@` 文本；在光标或文本未变之前抑制自动重开。编辑、移动光标到新触发状态或根变化后按现有 prompt 语义重新评估。
6. `undo`/`redo`、删除、鼠标定位、粘贴、视图切换后，面板状态必须与当前文本、光标和根一致；文件/目录采纳及目录进入各作为单步可撤销编辑。

## 5. 扫描与状态更新

### 5.1 根同步

事件循环在下列时机为相关 lx pane 同步有效根：PTY cwd 更新后、pane 创建/工作区切换后、每次准备提及扫描前。计算方式是 `pane.cwd.or_else(workspace_cwd_for_pane)`；不能使用当前进程 cwd、右侧 prompt 的根或其它 pane 的 cwd。对未启动 PTY 但有工作区路径的 pane 仍可使用回退根。

新根与旧根不同：递增扫描代号、清候选和在途标记、关闭旧候选；若 `mention_trigger` 在当前输入/光标仍有效，则进入等待扫描状态。根相同但输入查询改变，只在已缓存列表中本地过滤，不重新遍历目录。根无法得到时取消提及面板，底边不显示伪路径；保留输入文本。

### 5.2 后台扫描

事件循环只对处于 lx 视图、当前可见且具有有效 `@` 查询的 pane 发起 `spawn_blocking` 扫描，调用现有 `files::scan(root)`。结果通过新增的 pane 定向事件回主循环，附 pane id、根与扫描代号。避免输入每个字符都重扫；同一根的候选可在 pane 内缓存。现有扫描遵循根目录 `.gitignore`，跳过隐藏目录、常见构建目录和符号链接，设条目上限；不另加扫描器。

结果到达时若 pane 已关闭、根变更或代号不匹配则丢弃；若 pane 暂时不可见，结果可以写入该 pane 的有效缓存，但不显示浮层，待 lx 视图恢复后再按当前查询评估。扫描根不可访问或结果为空时面板无可选项；不得让 `Enter` 误采纳旧项。扫描是后台 IO，不阻塞事件循环或渲染。

### 5.3 选择与目录范围

使用现有 `mention_trigger` 规则：`@` 位于行首、空白或 `[` 之后，查询字符有效，围栏代码块内不触发。候选使用 `filter_mentions` 的排序与上限，空查询列出根下候选。目录进入后把触发文本写成 `@src/`，下一次过滤限定在该目录；再次 `Shift+Enter` 可以进入下一级。文件和文件夹的 `Enter`/点击均使用 `mention_insertion`，确认文本带尾随空格。

`Shift+Enter` 高亮文件、没有可见子项的文件夹或空候选时不修改文本，也不换行；面板仍保持当前状态。普通输入、退格、左右移动按既有编辑器规则重算面板。无面板时 `Shift+Enter` 仍换行，`Enter` 保持现有预留行为。

## 6. 渲染与几何

### 6.1 提及面板

以 `src/ui/main_content/lx.rs::layout` 得到的 `input: Rect` 为唯一定位依据：面板 `x = input.x`、`width = input.width`、底边紧邻输入框顶边，向上占用可用行。根据 pane 内容区高度限制面板行数；至少要放下上下边框与一行候选才绘制。空间不足时不挤压或移动输入框，也不越过 pane 内容区。输入框因文本增加高度时，面板跟随新 `input.y`，宽度不变。

建议在 lx 渲染模块内提供一个纯几何函数，统一返回面板 `Rect`、候选内容区、可见索引区间和滚动命中区域；渲染、点击、悬停、滚轮都用同一份计算结果。现有 `ui/widgets/command_panel` 可复用条目颜色、边框及滚动逻辑，但它默认按内容收缩宽度；实现必须确保本面板强制使用 `input.width`，不得靠填充标题文字撑宽。若修改通用 widget 的宽度策略，应保持其它调用方默认行为并增加针对性测试；若局部绘制更小，优先局部实现。

视觉上使用现有 `style` token：文件、目录分色；高亮、边框、标题和滚动条与 prompt 提及面板一致。所有新用户可见文案放进 `src/ui/text.rs`。候选名称和路径需按单元格宽度截断，不写到面板外；面板浮层绘制顺序在 lx 基础内容之后，覆盖其下的旧字符与样式。内容为空、扫描中或无匹配时采用固定尺寸的状态行，避免面板因为加载/过滤反复改变横向宽度；具体英文文案在实现前以 `text.rs` 统一收口。

### 6.2 pane 底边路径

路径只绘制于 `PaneView::Lx` 的外框底行，属于 `src/ui/panes.rs` 的只读渲染，不修改 pane 状态。保留左右角与两侧一格间距。宽度计算用 `unicode-width` 的终端列数，不用字节数或 `.chars().count()` 代替。

布局决策顺序：先计算底边可用列数；完整路径能容纳则显示完整路径；否则取 `Path::file_name()` 的末段（根目录等无末段时回退完整路径）；末段仍超宽则按字符边界和终端列宽截断并加 `…`；若可用宽度连省略号也放不下，就不绘制路径。禁止改写角字符、覆盖顶边的视图切换按钮或改变底边高度。非 UTF-8 路径以 `to_string_lossy()` 显示，但扫描根仍保留原始 `PathBuf`；无法生成合法相对候选的文件由既有扫描规则跳过。

## 7. 输入与鼠标路由

`src/input/` 把 `Shift+Enter` 保留为可区分的 lx 行为，具体是否进入目录由 `app/update` 根据当前提及面板决定，避免在输入层读取 pane 状态。路由优先级为：全局退出/浮层规则 → lx 粘贴参照 → lx 提及 → lx 块命令 → 普通编辑。提及打开时 `↑`/`↓` 循环高亮、`Enter`/`Tab` 采纳、`Shift+Enter` 进入文件夹、`Esc` 关闭；其它编辑键继续更新输入并重算触发。

鼠标按下优先检查可见提及面板候选，命中即先聚焦所属 pane，再采纳被点项；未命中时继续既有入口按钮、输入框、滚动条和整页选择。面板内滚轮先于 lx 输入滚动，调整候选视口且不改变输入光标或高亮；滚轮在面板外保持原行为。滚动后点击按实际可见索引命中，不能用未滚动的数组索引。面板关闭、pane 视图切走或 pane 删除时不得留下可点击区域。

## 8. 边界与失败处理

| 情况 | 预期 |
| --- | --- |
| pane cwd 尚不可得 | 以工作区路径显示和扫描。 |
| pane cwd 与工作区路径都不可得 | 不发扫描、不显示路径和候选，`@` 保留为普通输入文本。 |
| 轮询 cwd 失败 | 保留最近有效 pane cwd；不抖动到工作区路径。 |
| 终端 `cd` 后新目录不可访问 | 旧候选作废；面板显示空结果/不可用状态，不回退旧根。 |
| 扫描在途时再次变根 | 旧代号结果丢弃；只采纳新根结果。 |
| 切换 pane/tab/视图 | 各 pane 状态隔离；不可见面板不吃当前 pane 的按键或鼠标。 |
| 输入区高度/宽度不足 | 隐藏浮层，不移动输入框；可用空间恢复后依据状态重新绘制。 |
| 有已有块命令或粘贴面板 | 保证互斥；粘贴参照按已有优先级处理。 |
| 路径/候选含 CJK 或长文件名 | 以终端显示列宽计算，保持字符边界，不溢出。 |
