# TUI 统一输入快捷键与全文本选择设计

> 状态：待用户审核；本文不是实现完成记录。
> 范围：lx 的 TUI。浏览器设置页继续使用浏览器原生输入行为。

## 1. 目标与已确认边界

1. TUI 内所有真正可编辑的输入框支持同一套基本编辑快捷键。范围包括 lx、prompt、ask 手写答案、todo 行内编辑、页重命名、工作区/节点/会话重命名、worktree 查询、草稿命名、引用路径与引用搜索等弹窗输入。菜单、确认按钮和终端程序本身不是 lx 输入框。
2. 当前可见的 TUI 文字和边框都能鼠标选择：终端输出、lx 历史/输入、prompt、todo、ask、lx 后台任务（Processes/Agents，含 agent 列表行与详情正文）、侧栏、标签栏、工具栏、弹窗、toast。选区允许跨区域。隐藏、折叠及被不透明弹窗遮住的底层内容不进入当前画面选区。
3. 单击/拖动按字符选，双击按 Unicode 词边界选词，三击按真实换行分隔的逻辑行选整行；三击选区裁掉行尾填充空白、保留行首缩进，全空白行不形成选区。窄窗口产生的视觉折行不改变三击单位。参考实现的点击计数条件为同一屏幕格、间隔小于 400 ms，计数 1→2→3→1。
4. 选区松开后保持反显，**不自动复制**。有非空选区时 `Cmd/Ctrl+C` 才复制；复制成功或失败都不清选区。下一次点击其他位置清除；滚动、窗口缩放、正常内容刷新不清除仍有原文的选区。原文被删除、弹窗关闭或页面/会话切换使归属失效时清除。
5. 无选区时，`Ctrl+C` 在终端窗格继续进入 PTY；lx 页清空当前输入（ask 编辑态清空手写缓冲，`/resume` 历史面板仍复制会话 id）；其它应用输入框与阅读区不动作。复制键不加 Shift。只读区的 `Cmd/Ctrl+X` 不动作；可编辑选区的剪切须先写剪贴板成功，再删除并记录一次撤销。
6. 终端程序启用鼠标上报时，普通鼠标事件继续交给程序；按 Shift 才进入 lx 选择。按钮、tab、关闭按钮、滚动条、拖动分隔线、拖拽排序先命中；可点击文字行的拖动改为选字，未位移的单击在松开时执行原动作；非交互正文保留双击/三击选词。todo/prompt 列表行与编辑器保留各自语义。
7. 复制是**屏幕所见的纯文本**：包括选中范围里的边框、标点、可见填充空格与视觉折行；行间插入 `\n`，不复制颜色/样式；拖选与双击选词不自动 `trim_end`，三击整行裁掉行尾填充空白、保留行首缩进，右侧滚动条 `▐` 作为边界。不把视觉折行还原成原文。宽字符的续格不重复输出字符。单击不形成非空选区时不复制。

### 1.1 与既有规范的冲突

`docs/standards/tui-design-requirements.md` 的“选择与复制”一节目前写着终端/lx 松开即复制、终端清选区、prompt 无选区复制全文、`Ctrl/Cmd+Shift+C` 复制模板块，以及终端选择只限窗格。这些均与本次已确认行为冲突。实现阶段须同步改写该节及相应按键说明，不能让文档与代码各说各话。

## 3. 核心模型

### 3.1 画面快照

新增只读、按帧生成的 `ScreenText`（归 `ui/`）：从**所有组件完成绘制后**的 ratatui `Buffer` 提取 `(x, y) → symbol / width / source`。只取最终可见层；覆盖在底层的浮层不允许透选。`source` 是稳定的可见内容身份，不是复制字符的替代物：复制始终从选择时的画面符号生成。

建议形状（供评审，具体命名可按现有风格调整）：

```rust
struct ScreenCell {
    symbol: String,                 // ratatui Cell::symbol；宽字符续格为空
    source: Option<TextSource>,     // 内容稳定定位；装饰性边框可用区域+位置
}

struct ScreenSelection {
    origin: ScreenPoint,
    cursor: ScreenPoint,
    unit: SelectionUnit,            // Character / Word / Line
    dragging: bool,
    snapshot: SelectedCells,        // 复制 payload 的冻结画面；不受 toast/动画改写
}
```

`ScreenText` 的生成顺序必须与 `render_cached` 一致：侧栏/标签栏 → 窗格/右栏 → 控件 → tooltip/toast → overlay → 选择反显。取样应发生在反显之前，避免把“选中样式”当原画面样式；复制只读取符号。若帧在 overlay 之后被 `Clear` 覆盖，取到的也必须是覆盖后的格。最后一次已提交帧存入事件循环，鼠标命中不重新绘制整页；窗口大小变化使旧帧尺寸不匹配时先刷新取样再允许选择。选择创建时仅冻结实际覆盖的格，不能每帧为未选中画面额外克隆整块 `Buffer`。

常见三类格的提取规则：普通格输出 `cell.symbol()`；宽字符续格不输出第二次；明确的空格格输出一个 U+0020。全空格但跨了多个格的范围仍是**有效选择**，复制得到对应空格，不用 `trim()` 判空。不可见控制字符、ANSI/OSC 序列不可能直接来自可见 `Buffer`，若组件写入了这些符号仍须在剪贴板入口拒绝或净化，不能把控制流送给终端外部程序。

屏幕缓冲只在事件循环持有最近已提交的帧快照，`app/` 不持有 `Frame`、`Buffer` 或 IO 句柄。`app/` 只保存纯数据的选择状态与源锚点；`ui/` 只读状态、根据最终可见格给出命中/绘制高亮。绝不在渲染过程中回写状态。复制与剪贴板写入在事件/平台层，不能由渲染函数触发。

### 3.2 稳定锚点与刷新

原文仍存在时保留高亮需要稳定身份，不能只记屏幕 `(x,y)`，否则滚动后会高亮错行。为选区的起终点及覆盖格建立 `TextSource`：终端用窗格 ID + alacritty 内容行/列；prompt 用页面 ID + 文本字节范围；lx 历史用会话/步骤/行身份与列，lx/ask 输入用编辑缓冲修订与字节范围；todo 用记录 ID + 行内偏移；弹窗用实例代次 + 输入/标签行；静态界面用组件 ID + 行/列。渲染侧只为**可见格**生成源映射，历史区复用现有 `PaneCache`，不得每帧重排全历史。

```rust
enum TextSource {
    Terminal { pane: PaneId, absolute_line: i32, column: u16 },
    Prompt { page: PageId, byte: usize },
    LxHistory { pane: PaneId, block: BlockKey, line: usize, column: u16 },
    Editor { owner: EditorId, revision: u64, byte: usize },
    Todo { id: TodoId, column: u16 },
    Overlay { generation: u64, row: u16, column: u16 },
    Chrome { component: ComponentId, row: u16, column: u16 },
}
```

这只是身份约束的草图，`PageId` / `BlockKey` / `EditorId` 等须映射到仓库已有稳定标识，不能仅因草图引入新的持久化 ID。边框或布局空格可用所属组件的稳定位置；文本格则必须使用内容锚点。一个选择跨多个组件时，冻结 payload 按选中当时屏幕顺序排列，后续高亮仅绘制仍能在当前帧匹配到的源格。若两个端点任一归属消失，整个选区失效；只因滚出视口暂时不可见则不算消失。

选择时冻结 `SelectedCells` 的**字符与行列形状**供之后复制，所以动画或 toast 文案刷新不会偷偷改变待复制结果；源锚点只用于在后续帧重定位高亮。内容滚走后没有可见高亮，但选区仍存在；滚回来重新绘出同源格。缩放时按源锚点重新映射可见格；新折行只改变高亮位置，冻结的复制 payload 仍与当初选到的屏幕一致。若源身份失效，清除整段选择，避免把旧文字投影到同位置的新内容。

跨区域拖动采用屏幕阅读顺序 `(row, col)` 扩选；终端鼠标上报例外见 §4。复制从冻结画面逐格串接：宽字符仅首格输出，行末保留选择覆盖的空格，跨行插入 `\n`，控制字符拒绝进入剪贴板。边框及图标字符照原样输出。不把 ANSI 颜色、隐藏历史、tooltip 下层或占位的不可见格当文字。

```rust
fn selected_screen_text(cells: &SelectedCells) -> String {
    // 首尾行只取锚点覆盖的列；中间行取整段屏幕列。
    // 每个视觉行之间插入 '\n'；行尾空格、边框和软折行原样保留。
    // 宽字符续格跳过，但一个宽字符只要选中任一半就输出一次。
    // 空间复杂度与被选中的可见格数成正比。
    todo!()
}
```

上面的 `todo!()` 只用于设计伪代码，生产实现不得留下该占位。复制仍以选择发生时的画面为准；缩放导致当下屏幕重排，不会改写已冻结的复制结果。这与参考 codex 的“从原始段落重建复制文本”不同，是用户明确要求保留边框与视觉换行后的结果。

### 3.3 可编辑文本选区

可编辑控件还需要本地文本范围，才能实现选区替换、Backspace/Delete、剪切与撤销。保留/扩展 prompt 与 lx 现有范围，给 `TextInput` 增加 `anchor` 和有界 undo/redo 快照；ask 继续复用 lx 核心。屏幕选区的焦点若落在可编辑输入框，必须同步为该编辑器的字节/字符范围；不再维护两份互不相知的高亮。跨出输入框后成为只读屏幕选区，不允许一次输入把其他区域删掉。

单行 `TextInput` 的快照至少含文本和光标；一次粘贴、替换或剪切是一条撤销记录。撤销后光标与选区恢复，新的编辑清空 redo。保留单行净化规则（换行/Tab → 空格、丢弃控制字符）；todo 和弹窗现有长度限制在**净化后**检查。todo 列表删除撤销仍是独立槽：编辑中 Ctrl+Z 撤销文本，退出编辑后 Ctrl+Z 撤销删除。

## 4. 事件与优先级

1. `Mouse Down`：按钮、tab、关闭按钮、滚动条、分隔线、拖拽排序先处理。只读文字（含 task/ask/toast/浮层正文）直接启动屏幕选择；可点击文字行启动选择并登记延迟点击，不立即执行动作。Shift/终端鼠标模式仍可强制屏幕选择。新点击先清旧选区；点击弹窗外沿用现有关闭语义。
2. 在同一格、400 ms 内按下第二/第三次，按 codex 规则得到 `Word` / `Line`。双击 todo/prompt **文字**不进入编辑；非文字行区域保持原命中。拖动时以初始选择单位扩展，反向拖动也不能把起始词/行切断。
3. `Mouse Drag`：只更新选择终点与可见高亮；按钮、滚动条、分隔线先于选择，条目文字产生位移后转为选字。Shift+拖动在终端鼠标上报模式下不转发 PTY；普通事件仍转发。
4. `Mouse Up`：只将 `dragging = false`；不写剪贴板、不清高亮、不触发已开始选择范围上的卡片折叠。延迟点击若全程未位移，补执行原动作；只要产生过位移就只保留选区，不执行点击。折叠卡片单击后再延迟 400ms 才切换，双击/三击在第二次按下时取消待定切换。可见屏幕选区期间暂停 toast 过期。
5. `Key`：先处理 Ctrl+Q；已存在非空选择时 `Cmd/Ctrl+C` 全局复制；否则终端 `Ctrl+C` 原样转发，其他输入/阅读区不动作。`Cmd/Ctrl+X` 仅可编辑选区处理。其余键依焦点/浮层进入编辑器或 PTY。
6. `Paste`：终端 Paste 事件与 `Cmd/Ctrl+V` 按键回退共用同一 `paste_into_focused_editor`。只收到快捷键时后台读取系统剪贴板并把结果送回事件循环；回投携带目标实例/修订号，焦点已变则丢弃，防止粘进错误输入框。终端 PTY 保持 bracketed paste 包装。不得在渲染或事件循环同步等待平台剪贴板程序。

```rust
struct PasteTarget {
    focus: FocusedContainer,
    pane: Option<PaneId>,
    overlay_generation: Option<u64>,
    editor_revision: u64,
}

// Key(Mod+V) -> 捕获 PasteTarget -> spawn_blocking(read_clipboard)
// -> AppEvent::ClipboardRead { target, result } -> 校验目标 -> handle_paste_event
```

如果终端同时发送 Paste 事件与 Mod+V 按键，优先使用终端给出的 Paste 内容，取消仍在等待的回退读取；不能靠比较文本值去重，因为用户连续粘贴同一内容两次必须插入两次。终端协议没有“这两个事件来自同一次物理粘贴”的事务 ID，因此只能采用有界短等待窗口再启动按键回退；窗口之外的迟到 Paste 事件与新的粘贴无法可靠区分。这个终端兼容性限制应做成可复现测试，不能在文档里承诺绝对去重。回退读取出错只在当前输入目标反馈一次，不能把空串当成功结果。输入目标关闭/会话切换后来的结果直接丢弃，不提示到新焦点。

### 4.1 剪贴板确认语义

`write_clipboard(&str) -> bool` 不可直接用于“写成功后删除”的剪切事务：现有 bool 对后台原生复制只有**线程已启动**的含义，OSC 52 也没有终端确认。因此新建有结果回投的原生剪贴板写入任务，结果进入事件循环；提交时验证编辑器实例、选区范围与修订号仍与发起时相同，才执行删除并生成一条 undo 记录。等候期间允许用户继续操作；若状态已改变，结果不再删除任何文字。仅 OSC 52 可用而没有可确认的原生写入结果时，剪切不删除原文并给出失败反馈。普通复制可继续使用现有尽力而为路径，但 toast 不能把“线程已启动”描述成已确认落入系统剪贴板。

## 5. 统一输入快捷键

`Mod` 表示终端实际送达的 `SUPER` 或 `CONTROL`；macOS 终端可能拦截 Cmd 组合，Ctrl 变体必须可用。输入层只映射按键，`app/update` 按编辑状态执行业务。按键无对应目标时吞掉，不落进隐藏 PTY。

| 快捷键 | 编辑态语义 | 冲突处理 |
| --- | --- | --- |
| `Ctrl+A` / `Ctrl+E` | 行首 / 行尾 | 单行输入框即全文首尾；全选后光标移动取消全选并折叠到选区边缘 |
| `Mod+C` | 有选区时复制；选区保留 | lx 页无选区 `Ctrl+C` 清空当前输入；终端 Ctrl+C 仍进 PTY；其它应用输入/阅读区无选区 no-op |
| `Mod+X` | 仅剪切可编辑选区 | 写剪贴板成功后删除；只读区 no-op |
| `Mod+V` | 读取剪贴板并粘贴；终端 Paste 事件同一路径 | 去重同一次按键产生的 Paste 事件，不能插入两遍 |
| `Mod+Z` | 撤销一次文字编辑 | todo 编辑态不触发列表删除撤销；引用搜索不再用 Ctrl+Z 回退目录 |
| `Mod+Shift+Z` / `Ctrl+Y` | 重做 | 无历史时 no-op |
| `Ctrl/Alt+Left/Right` | 按词移动 | 在终端窗格不截获 PTY 的组合 |
| `Ctrl/Alt+Backspace/Delete`、`Ctrl+W` | 按词删除 | 可编辑目标内执行；保留已有 lx/prompt readline 语义 |
| `Home/End` | 行首/行尾；单行框即全文首尾 | 不改变 Enter、Esc、Tab、上下键的业务语义 |

`Ctrl+U/K/E` 等未冲突的既有 lx/prompt 编辑能力可保留。页重命名、弹窗名称、todo、ask 与 lx/prompt 的键集合须有同一组参数化路由测试。引用搜索的上级目录操作改由现有 Esc/界面入口承担，避免 `Ctrl+Z` 同时表示“撤销输入”和“回退目录”。菜单里的“复制路径/引用”显式命令与按钮继续存在；它们不属于输入框无选区复制。

## 6. 模块归属与不变量

- `src/input/`：唯一快捷键翻译；不可访问剪贴板、UI `Buffer` 或数据库。
- `src/app/state/`、`src/app/update/`：纯数据选择会话、编辑器历史及转移；不做 IO，不以样式判断内容。
- `src/ui/`：最终画面文本索引与高亮绘制；只读状态，基于 ratatui Buffer，不直接写 stdout。
- `src/event/`：鼠标优先级、目标代次检查、异步剪贴板回投与 toast；lx 页反馈必须走 `pane.lx.toast`。
- `src/platform/`：OS 专属剪贴板读取，按 cfg 门控；复用现有写入策略，失败可报告、不能阻塞高频事件循环。
- 不新增数据库表/迁移；不改变 agent 提示词或设置页资源；不改 TUI 恢复顺序。
- 生产代码单文件不超过 1000 行；`mouse/press.rs` 已有约 860 行，新增选择逻辑应抽到职责单一的模块，不把大段规则继续塞进现有函数。

## 7. 验收与风险

精确测试覆盖：三击点击计数边界、Unicode/CJK/宽字符、跨区域和边框复制、视觉折行与可见空格、弹窗遮挡、鼠标上报的 Shift 选择、控件优先、选中后不自动复制、`Mod+C` 后不清高亮、点击别处清除、滚动/缩放/原文失效、所有编辑框的粘贴/撤销/重做/全选/剪切、todo 两套撤销、异步粘贴焦点竞态与失败。交互与外观最终仍需用户 `cargo run` 实测。

主要风险是跨组件稳定源映射和全屏画面快照的内存/渲染成本。只保留最近一帧可见格与一段已选择的冻结格；历史行身份复用现有缓存，不拷贝完整聊天/终端回滚缓冲。实现时用窄屏、长历史、持续输出场景测选择后帧耗时与内存，若超出当前帧预算则先优化索引构建，不以清除选区规避已确认行为。
